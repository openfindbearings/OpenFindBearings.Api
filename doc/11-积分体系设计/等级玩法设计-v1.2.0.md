## 〇、设计总原则

1. **等级是"沉淀勋章"不是"经济杠杆"**：升级奖励一次性、特权只到外观/曝光层；
   赚取倍率与免费额度只归商户等级通道，个人等级不给倍率——防双轨叠倍套利。
2. **合规红线不破**：升档礼仍遵守"不可充值、不可提现、不可折现、不可转让"；
   个人升档发轴承币、商户升档发商家金，两币无互转路径。
3. **三线单向不循环**：行为→赚币→段位推档一条主线；成就=旁支纯荣誉（不产币）；
   段位升档=一次性出口。杜绝"成就刷币推等级、升级返成就"的循环农场。

## 一、双轨等级总览

| 轨道 | 梯子 | 输入 | 降级 | 特权性质 |
|---|---|---|---|---|
| 个人段位（PointLevel） | 十档：倔强青铜~最强王者 | 累计获得轴承币 TotalEarned 落档 | 不降级、无赛季（累计成长线） | 铭牌彩牌 + 一次性升档礼 + 曝光带牌；无倍率/额度 |
| 商家等级（MerchantGrade） | 四档：入驻Lv1~金牌Lv4 | 认证态 + 在售数 + 金库累计重算 | 实时重算 + 15 天保级缓冲（经营资质线） | 成员 buff 梯子 + 置顶折扣 + 一次性升档礼 + 角标曝光 |

段位名映射（Admin "等级段位"tab 可随时自定义，Name 列直改实时生效）：
Lv1 倔强青铜 / Lv2 坚韧青铜 / Lv3 秩序白银 / Lv4 璀璨白银 / Lv5 荣耀黄金 /
Lv6 华彩铂金 / Lv7 永恒钻石 / Lv8 至尊星耀 / Lv9 傲世星耀 / Lv10 最强王者。
色带（Taro 铭牌底色按等级号就近落带，与段位名前缀对齐）：
Lv1-2 青铜、Lv3-4 白银、Lv5 黄金、Lv6 铂金、Lv7 钻石、Lv8-9 星耀、Lv10+ 王者。

## 二、个人段位玩法

1. **升档礼**：`PointLevel.LevelUpBonus` 列（Lv2~10 种子 10/15/20/30/40/55/70/90/120，
   Lv1 恒 0），Admin 档位表可调。跨档时由 PointsService 在**每次入账成功后**统一结算：
   凡已达档且未领过的一次性补发（跳档合并到账），grantType=`level_up_bonus`。
2. **终身一次闸**：幂等双保险——认领台账 `PointRewardClaims` + 流水 BizId
   `levelup:{userId}:{升档号}`，每用户每档终身只发一次；升档礼入账再触发的跨档顺路补发，
   档位有限必然收敛。不回拨、不追缴、无降级议题（段位只升不降）。
3. **升级可见性**：`/api/points/account` 下发 `nextLevelMin/nextLevelName/nextLevelBonus`
   （积分页进度条"距升 X 还差 Y 币 + 升档礼预告"）；签到响应回传 `level/levelName/leveledUp`
   （跨档播"恭喜升段"toast）。
   v1.1.0 起另有**段位详情页**（Taro `pages/my/level`，对标京东会员/美团会员中心版式）：
   顶部段位 tab 条（横滑+当前档下划线）、段位大卡（色带底+进度条+升档礼）、可享权益宫格、
   入口行（任务中心/勋章墙/收支明细/规则页）；数据源新端点 `GET /api/points/levels`
   （全档位+本人落档+已领档——按流水 BizId 存在性判定，与发放侧同键天然一致）。
4. **铭牌（外观特权）**：昵称旁彩色段位徽标（青铜~王者七色带）。曝光面：寻货发布人视图应答行
   展示"经办人段位"彩牌（真人信任信号，批量落档防 N+1）。
   v1.1.0 版式调整（对标主流账号卡）：**用户信息卡手机号行改挂段位彩牌**（点击进段位页），
   轴承币卡头部彩牌撤除防双份；积分页彩牌保留并作为段位页第二入口。
5. **成就纯荣誉化**：勋章点亮只记荣誉分与称号资格，**不再发币**（原 achievement_unlock
   甜头连同 `AchievementDefinition.RewardPoints` 字段一并删除，规则行停用留档）。

## 三、商家卡级玩法（v1.2.0 重构：认证是类型、卡级是经营档位）

**模型定案**：认证是"类型"不是"等级"——`Merchant.IsVerified` 加独立证照审核链，与卡级徽章**并列**展示；
等级改称"卡级"，只表达经营水平，认证名不写进等级名。

1. **卡级序列（单调）**：注册商户 Lv1（未认证，无卡级）/ 铜卡 Lv2 / 银卡 Lv3 / 金卡 Lv4。
   钻卡只作规划不进枚举。枚举值重排为单调（Registered=1/Bronze=2/Silver=3/Gold=4），
   存量库由迁移 `AddMerchantCardTiers` 幂等互换旧值（旧 Verified↔Bronze、旧 Premium↔Silver），
   不做"历史选定视为谈成"的数据回填。
2. **升档条件**（同一根标尺，全部可衰减）：
   - **铜卡** = 完成平台证照认证；未认证一律只显示"注册商户"并引导认证（杜绝未认证挂高卡误导买家）；
   - **银卡** = 已认证 + 公域可见在售 ≥ `Business.MerchantGradeOnSaleMin`（默认 5）
     + 近 `Business.MerchantGradeWindowDays`（默认 180）天**计分成功撮合** ≥ `Business.MerchantSilverDealMin`（默认 1）；
   - **金卡** = 已认证 + 在售达标 + 窗口期成功撮合 ≥ `Business.MerchantGoldDealMin`（默认 3）。
   在售门槛与匹配机制自洽：`SourcingMatcher` 只匹配公域可见在售的商家，零库存"现找货"本就选不中。
3. **成功撮合的唯一来源**：需求方对自己选定的合作提交成交回执且"谈成"。
   选定（`Adopt`）只是意向不计分；没谈成（没货/加价/拖延/其他）记负信号不计分；不填为中性、不惩罚需求方。
   窗口期滑动即自然衰减——**终身累计不得作为可降档位的输入**，金库（`TotalEarned`）彻底退出定级、仅作展示。
4. **升档礼**：升到铜卡 +50 / 银卡 +150 / 金卡 +300 商家金入金库（`Business.MerchantGradeBonusLv2/3/4` 可调，0=不发）。
   BizId=`gradeup:{merchantId}:{档序}`——**每商户每档终身一次，复升同档不重发**。
5. **保级缓冲**：重算发现应降档时挂 `Merchants.GradeGraceUntil=now+Business.MerchantGradeGraceDays`
   （默认 15 天，0=立即降），期内维持原卡级与成员 buff；期内恢复达标自动清钟；到期仍不达标才落实降档。
   撤销认证（平台执法）与释放回公海不走缓冲直接落级。
6. **降级纪律**：不回拨已发升档礼、降档无额外惩罚（只停权益）——掉级翻译成召回路径。
7. **卡级详情页**（Taro `pages/merchant/level`）：头部彩牌 + 保级倒计时 + 距下一档进度
   （在售 X/阈值、近 N 天成功撮合 Y/阈值、"还差几件/几次"）+ 四档阶梯 + 权益宫格；
   数据源 `GET /api/points/merchant-grade?merchantId=`（**在职成员校验**）；
   后端只回 `nextTier{requiredOnSale,requiredDeals,metOnSale,metDeals}`，前端不自推阈值组合。
8. **搜索权重加权**：`MerchantGradeExtensions.Rank` 即卡级序数（枚举已单调，不再需要历史映射表）；
   商家搜索主排序与轴承在售商家列表按卡级序数（等级高者靠前），查询期实时打分、不持久化权重字段（防双份漂移）。


## 四、数值锚点（节奏调参依据）

- 曲线形态：档距 100/200/300/400/600/800/1000/1200/1400 温和凸递增，前置快后置慢（主流成长等级范式）。
- 日上限=最快升档硬地板（理论极限 ~150 币/日）：Lv10 硬核最快 ~40 天、活跃 ~100 天、轻度 ~500 天；
  首日新手一次性礼可直接冲 Lv2。
- 升档礼全满 +450，占满级阈值 7.5%（正反馈不通胀）。
- 调参阀门：档位阈值/升档礼 Admin 实时改；上线后按真实日活分布微调档位数据，不改代码。
