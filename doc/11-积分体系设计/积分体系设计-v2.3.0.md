## 一、M1-b 商城虚拟权益（已实现，六端绿）

### 1.1 范围界定（本期实装 vs 预留）
| 类别 | 状态 | 说明 |
|---|---|---|
| **置顶卡 PinCard** | **已实装履约** | 商户花积分为自己某件**在售**商品买曝光：该型号商家列表置顶 N 小时 + 买家侧"置顶"角标 |
| 寻货次数包 SourcingPack | 预留（履约器明确拒绝） | 需先设计"额度银行"（购买额度如何与每日免费额度/硬顶叠加），不做半截生效 |
| 实物礼品 Gift | 预留（M1-c） | 商家挂礼 + 平台托管 + 确认收货结算入金库 |

> 预留类别在 `RedeemAsync` 中返回"该权益即将上线"，**不扣分不建单**——宁可不生效也不半截生效。

### 1.2 核心设计决策（承 v2.1.0 并落地）
1. **平台统一定价**：价格由 Admin 设定而非商户自定，杜绝"商户 A 挂 1 分礼品给商户 B"式定向积分转移。
2. **闪购=限时改价窗口**（零成本运营手段）：`FlashPrice + FlashStart/FlashEnd`，窗口内自动取闪购价并显示划线原价与"闪购"角标，窗口外自动回落——无需发版即可做活动。
3. **限量库存制造真实稀缺**：`Stock=-1` 不限；限量商品 `SoldCount` 累加，兑完显示"已兑完"且不可兑换。
4. **兑换顺序固定为"全量校验 → 扣分 → 履约"**：`DeductAsync` 内部即提交事务，因此商品下架/库存/越权/非在售等一切可预见失败都必须在扣分前拦掉；履约阶段异常则**原路退分**并把订单标 Failed。
5. **退款不查规则表**：新增 `IPointsService.RefundAsync`，金额取订单快照，规则被停用/改值都不影响用户拿回自己的分；bizId=`mall_refund:{orderId}` 幂等。
6. **订单快照**：`ItemKey/ItemName/PointsSpent` 落订单行，目录后续改价/改名/删行都不影响历史凭据展示与对账。
7. **置顶可续期不亏时长**：`MerchantBearing.Pin()` 以"未过期则从到期时间续加、已过期则从现在起算"为基准。
8. **注销级联**：兑换订单随账号清零（与积分流水同口径）；已生效的置顶权益挂在 MerchantBearing 上，不随注销回滚。

### 1.3 数据模型（迁移 `20260926203938_AddMall`）
- `MallItems`：Key(唯一)/Name/Description/Icon/Category/PointPrice/FlashPrice/FlashStart/FlashEnd/DurationHours/Stock/SoldCount/Enabled/SortOrder。
- `MallOrders`：UserId/ItemId/ItemKey/ItemName/PointsSpent/Status/TargetRef/Remark/FulfilledAt，索引 `(UserId, CreatedAt)`。
- `MerchantBearings.PinnedUntil`（新增列，可空 timestamptz）。
- 迁移内嵌**初始置顶卡目录种子**（幂等 NOT EXISTS，含全部 NOT NULL 列）：
  - `pin_24h` 24小时置顶卡 = **120 积分**
  - `pin_72h` 72小时置顶卡 = **320 积分**
  - 定价锚（承 v2.1.0）：月入约 180 分 → 24h 落在 100-150 区间、72h 落在 250-400 区间。
- 目录种子**只走迁移不走 SeedData**（存量库 SeedData 按 Users 非空短路；新库迁移同样执行，单一事实源无漂移）。

### 1.4 领域/应用/基础设施
- `MallItem`：`EffectivePrice(nowUtc)`（闪购窗口结算）/`IsFlashing`/`HasStock`/`ConsumeStock`/`Update`（Key 与 Category 不可变——履约策略与历史快照锚定它们）。
- `MallOrder`：`Create`（快照）/`MarkFulfilled`/`MarkFailed`/`MarkRefunded`。
- `MerchantBearing`：`PinnedUntil` + `IsPinned(nowUtc)` + `Pin(nowUtc, hours)`。
- `IMallItemRepository`/`IMallOrderRepository` + 实现（目录实时读不缓存；订单分页；注销 ExecuteDelete）。
- `IMallService`/`MallService`：目录（含余额）/兑换/我的订单；兑换内含越权守卫（`GetActiveByUserAndMerchantAsync` 校验在职成员）与在售校验。
- `IPointsService.RefundAsync`（新增）+ `PointTransaction.TypeMallRedeem`/`TypeMallRefund` 常量。
- **Admin 端点直连仓储必须显式 `IUnitOfWork.SaveChangesAsync`**（不走 MediatR 管道）——本批同时补修了 M1-a 成就 Admin PUT 的同类漏提交。

### 1.5 买家侧曝光闭环
`GetMerchantsByBearingQueryHandler`：
- 商家级置顶态 = 该商家所有关联里**最晚的未过期 PinnedUntil**（一条在置顶期即整行置顶）。
- 排序 `OrderByDescending(IsPinned)`（稳定排序，其余保持原相对顺序）。
- DTO 新增 `IsPinned`/`PinnedUntil`；BFF `BearingMerchantItem` 透传；Taro 轴承详情商家行渲染橙色"置顶"角标。
- 判定统一用本次查询的同一 `now`，避免同页不同商家口径漂移。

### 1.6 端点
**API（5 个）**
- `GET /api/mall/items`（目录：生效价/闪购态/库存态 + 当前余额）
- `POST /api/mall/redeem`（body: itemId/targetRef/requestId；失败 400 带用户可读原因）
- `GET /api/mall/orders`（我的兑换订单分页）
- `GET /api/admin/mall/items`（目录全量含停用，system.manage）
- `PUT /api/admin/mall/items/{id}`（编辑价格/闪购窗口/库存/时长/上下架/文案/排序，system.manage）

**BFF（3 个代理）**：`/mobile/mall/items`、`/mobile/mall/redeem`（PostWithResultAsync 透传失败原因）、`/mobile/mall/orders`。

### 1.7 前端（Taro）
- **商城 Tab 页**（原占位页替换）：余额条 + "去赚积分"、权益橱窗（闪购角标/划线原价/限量与已售/已兑完禁用态）、我的兑换列表（状态中文：已生效/失败已退分/已退款/处理中）、合规一行（不可充值/提现/转让）。
- 置顶卡兑换入口在**商品管理页**：在售商品行新增橙色"置顶"按钮 → 拉目录 → ActionSheet 选时长档（名称+价格）→ 确认框（余额足够="确认兑换"；不足="去赚积分"并跳任务中心）→ 兑换（`requestId=pin-{rowId}-{ts}` 幂等）→ 成功震动+toast。
- 轴承详情商家行"置顶"角标（曝光效果看得见）。
- 商城目录/兑换/订单服务层 `services/mall.ts` + config 路径三键。

### 1.8 Admin
- 新页 `Mall/Index`（商城管理）：目录列表（键/名称/类别中文/常规价/闪购价/闪购窗口/时长/库存/已售/上下架）+ 编辑模态框（价格、闪购价与窗口、时长、库存、排序、上下架、文案、图标键）。
- **时区规则合规**：闪购窗口 UTC 存储；列表用 `data-utc` 输出 ISO 串交全局 JS 转本地；编辑框 `datetime-local` 由 JS 做 UTC↔本地双向转换，提交走 `flashStartUtc/flashEndUtc` 隐藏域——**服务端零时区转换**。
- 菜单"系统配置"组下新增"商城管理"（system.view 可见，编辑 system.manage），**无新增权限键**。

## 二、部署注意事项（M1-b）

1. **API 必须跑迁移** `AddMall`：两表 + `MerchantBearings.PinnedUntil` 列 + 2 个置顶卡种子。验证 `__EFMigrationsHistory` 出现 `20260926203938_AddMall`。
2. 发布顺序：API（带迁移）→ BFF → Admin → Taro。BFF/Taro 先于 API 上线会出现目录 404（前端已 catch 静默，不崩）。
3. 置顶卡种子只在迁移落，新装库同样由迁移产生（SeedData 未参与），无双轨漂移。
4. 兑换扣分依赖 M0 的 xmin 并发令牌，余额不足抛 InvalidOperationException 已转"积分不足，去任务中心赚积分吧"。
5. Taro 商城 Tab 为既有页面替换（非新增路由），Metro 热更即可；商品管理"置顶"按钮同批生效。

## 三、后续路线（承 v2.1.0，未实施）

- **M1-c 金库+trickle+挂礼结算**：`MerchantPointAccount`/`MerchantPointTransaction`、成员审核/交易类赚分 trickle 平分（余数给最高等级家）、Gift 类别履约（商家挂礼+审核定档+托管+确认收货全额入金库+7 天自动确认+Admin 冻结退分）。
- **M2 buff+工会等级+帮派园地 UI**：成员 buff 取最高等级工会（无主工会）、工会 Lv1-4、商家管理页帮派建筑化。
- **M3 集体任务+工会排行**。
- **额度银行**（寻货次数包前置）：购买额度与每日免费额度/硬顶的叠加与过期规则。

> 不变量（承 v2.1.0）：不充值/不提现/不转让；商家收入永不开 RMB；buff 受 DailyLimit；金库不提分给个人；结算模型=燃烧作废；置顶平台统一定价+时限+角标；M1 仅包邮；单号必填；注册奖励绑手机号且默认停用待短信。
