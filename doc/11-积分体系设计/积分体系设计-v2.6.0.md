## 〇、术语统一：工会 → 商家（本批全链路改名）

定案：产品与代码统一使用"商家"名词，不再引入"工会"作为第二套术语（历史 v2.0.0-v2.5.0 文档保留原文不追改）。

- **代码标识符**：`GuildTask*` 实体/仓储/服务/Job → `MerchantTask*`，表名 `MerchantTaskDefinitions` / `MerchantTaskCompletions`，
  `GuildBuffs` → `MerchantBuffs`，`MemberGuildInfo` → `MemberMerchantInfo`。
- **对外契约**：grantType `guild_task` → `merchant_task`，金库场景 `guild_task_reward` → `merchant_task_reward`，
  bizId 前缀 `guildtask:` → `merchanttask:`，端点 `/api/points/guild-buff` → `/merchant-buff`、
  新增 `/merchant-tasks` `/merchant-ranking`，Admin `/api/admin/points/merchant-tasks`。
- **配置键**：`Business.GuildPremiumOnSaleMin` 等三键 → `Business.Merchant*`（AddMerchantTreasury 迁移未发布，种子直接改）。
- 迁移 `AddGuildTasks`（未发布、未进任何数据库）删除重建为 `AddMerchantTasks`，无历史数据迁移负担。
- M2 已上线面仅 Taro/BFF/API 三端同仓同步改名，无第三方消费者。

## 一、数据模型（两表，AddMerchantTasks 迁移）

- `MerchantTaskDefinitions`：任务定义。TaskKey 唯一（锚定台账与奖励 bizId，创建后不可变）；
  MetricKey 三值 `corrections`（成员纠错被采纳流水条数）/ `treasury`（金库入账总额）/ `products`（新上架商品数）；
  Period 1 周 / 2 月；RewardType 1 全体成员各得 / 2 金库入账；数值与开关 Admin 可配实时生效。
- `MerchantTaskCompletions`：完成台账。(TaskKey, MerchantId, PeriodKey) 唯一索引 = 周期防重铁闸，
  多副本并发结算靠它兜底；MetricValue 留痕便于复盘。
- PeriodKey 业务日界口径（BusinessClock）：周=业务周 Monday `yyyyMMdd`，月=`yyyyMM`。
- 种子：merchant_corrections_week（周·纠错 5 人·每人 +20）/ merchant_products_week（周·上新 5 件·金库 +100）/
  merchant_treasury_month（月·入账 300·每人 +50）+ `merchant_task` 发放规则（分值按任务定义 amountOverride 覆盖，
  照 achievement_unlock 先例；Personal 任务清单端点将 grantType 加入过滤集合防"自动发放"伪任务）。

## 二、结算中枢 MerchantTaskService

三指标全部复用既有仓储聚合查询（corrections→PointTransaction 计数、treasury→金库流水求和、products→MerchantBearing 计数），
服务只做周期窗口计算 + 达标裁决 + 防重结算 + 发奖编排。

**结算纪律（关键决策）**：

1. **金库奖励**（RewardType=2）：台账行与 `RewardTreasuryAsync` 入账**同批 SaveChanges**，原子提交；
   撞唯一索引=他轮已结算，`ChangeTracker.Clear()` 后跳过（防脏行连累同作用域后续保存）。
2. **成员奖励**（RewardType=1）：台账**先独立提交占坑**（占坑失败绝不发奖，杜绝并发双发）；
   随后逐人 `PointsService.GrantAsync`，bizId=`merchanttask:{task}:{商户}:{周期}:{用户}` 四段幂等，
   单人失败自吞不拖垮其余成员。
3. `merchant_task` 不在金库 trickle 白名单——集体任务发放不再二次上供（无循环计提）。
4. 达标即结算不等周期末（Job 每小时扫描，"raid 掉落即时发"体感）；多 Pod 并跑安全。

**排行口径**：月榜 = 本业务月金库入账（trickle+挂礼结算+任务奖励全部计入"商家实力"）降序 TOP 20；
取数深度 100，本商家在深度内回显真实名次，深度外总额单独回显 rank=0（前端展示"未上榜"）。
只展示商家名/等级/入账额——B2B 供给侧数据，无个人信息隐私负担。

## 三、端点与三端接线

- API：`GET /api/points/merchant-tasks`（成员视角=最佳商家，与福利卡同口径；含 completedTotal 累计达标次数）、
  `GET /api/points/merchant-ranking`、Admin `GET/POST/PUT /api/admin/points/merchant-tasks`（points.manage）。
- BFF：`/mobile/points/merchant-tasks`、`/mobile/points/merchant-ranking` 强类型透传（同 merchant-buff 模式）。
- Taro 任务中心新增两卡：**集体任务卡**（周/月标签+flex 比例进度条+奖励文案+已达成绿标+累计达标次数；
  散人显示加入引导）、**商家实力榜卡**（Top5+前三金银铜配色+我的商家分隔行回显）。RN 兼容：纯 flex、无百分比宽度、无 fixed。
- Admin：系统配置页新增"商家任务"tab（批量编辑表+新建表单；TaskKey 只读列展示不可改）。
