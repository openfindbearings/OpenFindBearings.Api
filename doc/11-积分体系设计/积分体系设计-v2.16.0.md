# 积分体系设计 v2.16.0（牌级有效期制 + 审计修复）

> 版本：v2.16.0 | 日期：2026-10-20 | 上一版：v2.15.0（商家卡级重构：金库退出定级）
> 本版性质：**定级周期改有效期制** + 一轮资金/计分安全审计修复。
> 档位口径与规则见《等级玩法设计 v1.3.1》，本文档记批次落点。

## 零、本版变更（v2.16.0）：有效期制 + 审计修复

1. **定级改 180 天有效期制**：`MerchantGradeService` 按 `GradePeriodStartAt` 起的本期成交定级；
   升级/续期即重发一期；到期按本期成交留档、零成交降至铜牌；在售连续不足超过保级期（默认 15 天）直接降普通。
   统计改按 `SourcingResponse.CountedAt`（首次计分固化时刻），不再按可变的 `FeedbackAt`。
2. **每日巡检**：新增 `MerchantGradeSweepJob`（业务日 03:00，Business.TimeZoneOffsetHours），
   结算到期续期/降档、在售不足保级到期，并负责到期前 7 天站内信提醒（`Notification.TypeMerchantGrade`）。
3. **集体任务结算任务**：`MerchantTaskSettlementJob` 正式注册为 `HostedService`——此前未注册，
   任务奖励（成员积分 + 商家金）从不自动发放，是商家金长期为 0 的原因之一。
4. **认证升铜牌升档礼修复**：`Merchant.Verify()` 不再直接写铜牌档位，改由重算按「认证 + 在售达标」补档，
   使普通→铜牌的升档礼在首次认证达标时正常发放（`gradeup:{merchantId}:{rank}` 幂等）。
5. **退款不计累计获得**：新增 `PointAccount.Refund`，退款只回冲余额与累计消耗，**不计入 `TotalEarned`**、
   不触发商家金上供与个人段位升档礼，堵住"反复退款刷等级奖励"。
6. **扣分幂等键按用户/商户隔离**：`PointsService.DebitAsync` 落库键加 `u:{userId}:` 前缀，
   `MerchantPointsService.SpendAsync` 加 `m:{merchantId}:` 前缀，防止不同用户/商户复用同一 requestId 时误判已扣或串账。
7. **普通档无商家加成**：`MerchantBuffs` 的签到、应答额度、纠错加成仅在铜牌及以上生效（普通档不再有 `Lv1` 档加成），
   与"普通无牌级权益"口径一致；福利卡升级提示同步改口径。

## 一、历史版本变更（v2.15.0）：商家卡级重构

1. **金库退出**：`MerchantGradeService.ComputeGrade` 去掉 `treasuryEarned` 入参与其账户查询；
   原先"因金库变动而空转重算"的调用点（商城兑换/自动确认/积分入账等）逐个摘除，
   重算改由**成交回执提交**与在售变化（上架/下架/审核）驱动。
2. **阈值配置键换血**（SystemConfig，实时可调，无需发版）：
   新增 `Business.MerchantGradeOnSaleMin`(5)、`Business.MerchantSilverDealMin`(1)、`Business.MerchantGoldDealMin`(3)、`Business.MerchantGradeWindowDays`(180)；
   删除 `Business.MerchantPremiumOnSaleMin` / `MerchantGoldOnSaleMin` / `MerchantGoldTreasuryMin`。
   保留 `MerchantGradeGraceDays`(15) 与 `MerchantGradeBonusLv2/3/4`(50/150/300)。
3. **计分成功撮合**：`ISourcingResponseRepository.GetCountedDealCountAsync(merchantId, sinceUtc)`
   ——统计 `IsCounted && FeedbackOutcome==Confirmed && FeedbackAt>=since` 的应答数；
   反刷四项（自关联排除 / 配对去重 / 需求方资格门槛 / 同 IP 异常检测）由回执命令处理器把关。
4. **回执反刷规则键**：`Business.SourcingFeedbackMinAccountAgeDays`(1)、`SourcingFeedbackIpWindowHours`(24)、`SourcingFeedbackIpMax`(5)。
5. **升档礼与保级缓冲不变**：升档礼每商户每档终身一次；降档先挂 `GradeGraceUntil` 保级钟，到期落实。

## 一、历史版本变更（v2.14.0）：商家等级在售口径统一


**问题**：同一商家可能出现"被寻货通知（`SourcingMatcher` 按公域可见匹配）却在等级里不计在售（`MerchantGradeService` 只算 `GetOnSaleByMerchantAsync` 出售中）"的口径矛盾，补货中商品对客户真实可询、却不算作商家的供给能力。

**变更**：
- `MerchantGradeService` 定级输入由 `GetOnSaleByMerchantAsync`（仅出售中）改为 `GetMatchableByMerchantAsync`（出售中 + 补货中 = 公域可见），`GET /api/points/merchant-grade` 同源换算；
- 寻货应答实力摘要 `onSaleCount` 改 `CountPubliclyVisibleAsync`（同一口径）；
- **成就仪表 `listing_count`（货架满满）保持不变（现货口径）**：历史进度与阈值已按现货口径固定，放宽会让存量商家凭空白送勋章，已在 `AchievementMetricKeys` 常量注释写明。

**影响**：等级为实时重算 + 降档 15 天宽限，口径放宽可能使部分商家档位即时上升（预期内，无回退风险）；金库指标与认证指标不变。

## 零、本版修复（v2.13.1）

**根因**：API 的持久化模式是"端点/行为显式 `SaveChanges`"，而成就写路径全踩在提交点之后：
- 签到端点：`PointsService.CheckinAsync` 内部先提交积分，**之后**才调成就累加（`PointsEndpoints`）→ 跟踪的变更无人保存
- 注册/登录中间件：成就 `IncrementAsync` 与 `GrantAsync` 提交时序交错，同样丢
- MediatR 事件 handler（纠错/寻货选定/上架）：`UnitOfWorkBehavior` 是 **SaveChanges 之后才 Publish** → handler 内成就变更必丢

（命令管线内直调的 `merchant_verified`/`sourcing_publish_total` 因随主命令一起提交，此前正常。）

**修复**：`AchievementService` 自持 `IUnitOfWork`，在 `ApplyAsync`/`UnlockLimitedByOrdinalAsync`
循环末尾统一 `SaveChangesAsync`，所有调用方一次修好；调用方旁路 `try/catch` 语义不变
（提交失败同样吞掉不反噬主流程）。早提交经核实不影响领域事件派发（`SaveChanges` 只更新审计字段，
事件由 `UnitOfWorkBehavior` 在 Publish 后显式 `ClearDomainEvents`）。

**历史回填**：迁移 `BackfillAchievementProgress` 从流水与业务事实表一次性回填——
`checkin_total`/`login_total`/`correction_adopted`=流水按 `GrantType` 计数、
`checkin_streak`=`PointAccounts.ConsecutiveCheckinDays`、`sourcing_selected`/`merchant_selected`
=`SourcingResponses.Status=2`、`sourcing_publish_total`=`SourcingDemands` 按发布人计数、
`register_total`=`Users` 每人 1、`listing_count`=`MerchantBearings.IsOnSale` 按商户计数；
冲突策略 `GREATEST`（进度只增不减）+ `COALESCE`（已点亮不熄），幂等可重复执行。
**同迁移顺带清理僵尸列** `AchievementDefinitions.RewardPoints`（实体已于 v2.12.0 删除该字段，
当时未出迁移，DB 残留无读写路径引用的死列）。

## 二、实现说明

- 两新端点均纯读接口，无迁移、无新表、无发放逻辑改动；等级数值口径全部沿用 v2.12.0。
- 前端等级名展示：个人侧来自 `/points/levels` 的档位表（Admin 改名即时生效）；
  商家管理页头部彩牌用前端映射（省一次接口），详情页用接口 gradeDisplay。
- 工具链：RN 构建刷屏的 `[GD-OPTS-DUMP]` 为早前调试热改进 node_modules 的遗留探针
  （不在 pnpm patch 内），已删除，重装即净。
