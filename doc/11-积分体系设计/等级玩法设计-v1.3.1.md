## 〇、设计总原则

1. **等级是"沉淀勋章"不是"经济杠杆"**：升级奖励一次性、特权只到外观/曝光层；
   赚取倍率与免费额度只归商户等级通道，个人等级不给倍率——防双轨叠倍套利。
2. **合规红线不破**：升档礼仍遵守"不可充值、不可提现、不可折现、不可转让"；
   个人升档发轴承币、商户升档发商家金，两币无互转路径。
3. **三线单向不循环**：行为→赚币→段位推档一条主线；成就=旁支纯荣誉（不产币）；
   段位升档=一次性出口。杜绝"成就刷币推等级、升级返成就"的循环农场。
4. **信任指标必须可衰减**：商户牌级对外承担"有货、被买家选过"的信号，
   任何输入都不得是终身累计；本期成交 + 实时在售，两条都可随时间自然回落。

## 一、双轨等级总览

| 轨道 | 梯子 | 输入 | 降级 | 特权性质 |
|---|---|---|---|---|
| 个人段位（PointLevel） | 十档：倔强青铜~最强王者 | 累计获得轴承币 TotalEarned 落档 | 不降级、无赛季（累计成长线） | 铭牌彩牌 + 一次性升档礼 + 曝光带牌；无倍率/额度 |
| 商家牌级（MerchantGrade） | 四档：普通~金牌 | 认证态 + 实时在售 + 本期成功撮合 | 180 天有效期 + 15 天在售保级期 | 成员 buff 梯子 + 置顶折扣 + 一次性升档礼 + 角标曝光 |

段位名映射（Admin "等级段位"tab 可随时自定义，Name 列直改实时生效）：
Lv1 倔强青铜 / Lv2 坚韧青铜 / Lv3 秩序白银 / Lv4 璀璨白银 / Lv5 荣耀黄金 /
Lv6 华彩铂金 / Lv7 永恒钻石 / Lv8 至尊星耀 / Lv9 傲世星耀 / Lv10 最强王者。
色带（Taro 铭牌底色按等级号就近落带，与段位名前缀对齐）：
Lv1-2 青铜、Lv3-4 白银、Lv5 黄金、Lv6 铂金、Lv7 钻石、Lv8-9 星耀、Lv10+ 王者。

## 二、个人段位玩法

1. **升档礼**：`PointLevel.LevelUpBonus` 列（Lv2~10 种子 10/15/20/30/40/55/70/90/120，
   Lv1 恒 0），Admin 档位表可调。跨档时由 PointsService 在**每次入账成功后**统一结算：
   凡已达档且未领过的一次性补发（跳档合并到账），grantType=`level_up_bonus`。
2. **终身一次闸**：幂等双保险——认领台账 `PointRewardClaims` + 流水 BizId
   `levelup:{userId}:{升档号}`，每用户每档终身只发一次；升档礼入账再触发的跨档顺路补发，
   档位有限必然收敛。不回拨、不追缴、无降级议题（段位只升不降）。
3. **升级可见性**：`/api/points/account` 下发 `nextLevelMin/nextLevelName/nextLevelBonus`
   （积分页进度条"距升 X 还差 Y 币 + 升档礼预告"）；签到响应回传 `level/levelName/leveledUp`
   （跨档播"恭喜升段"toast）。
   v1.1.0 起另有**段位详情页**（Taro `pages/my/level`，对标京东会员/美团会员中心版式）：
   顶部段位 tab 条、段位大卡（色带底+进度条+升档礼）、可享权益宫格、
   入口行（任务中心/勋章墙/收支明细/规则页）；数据源 `GET /api/points/levels`。
4. **铭牌（外观特权）**：昵称旁彩色段位徽标（青铜~王者七色带）。曝光面：寻货发布人视图应答行
   展示"经办人段位"彩牌（真人信任信号，批量落档防 N+1）。
   v1.1.0 版式调整：**用户信息卡手机号行改挂段位彩牌**（点击进段位页），
   轴承币卡头部彩牌撤除防双份；积分页彩牌保留并作为段位页第二入口。
5. **成就纯荣誉化**：勋章点亮只记荣誉分与称号资格，**不再发币**（原 achievement_unlock
   甜头连同 `AchievementDefinition.RewardPoints` 字段一并删除，规则行停用留档）。

## 三、商家牌级玩法（v1.3.0：180 天有效期制）

**模型定案**：认证是"类型"不是"等级"——`Merchant.IsVerified` 加独立证照审核链，与牌级徽章**并列**展示；
牌级只表达经营水平，认证名不写进牌级名。

1. **牌级序列（单调）**：普通 Lv1（未认证或在售不足）/ 铜牌 Lv2 / 银牌 Lv3 / 金牌 Lv4。
   枚举值 `Unknown=0/Ordinary=1/Bronze=2/Silver=3/Gold=4`；`Registered` → `Ordinary` 仅换名、不改值，
   无数据库变更。白金、钻石只预留命名，不进枚举与界面。
2. **牌级图标**：普通 `user`、铜牌 `medal`、银牌 `award`、金牌 `trophy`（两端 Lucide 既有图标）。
   等级页大卡面与四档阶梯用档位图标替代数字；商家名称旁的小徽章渲染为纯图标，不与名称争行宽。
3. **升档条件**（同一根标尺，全部可衰减）：
   - **铜牌** = 完成平台证照认证 + 公域可见在售 ≥ `Business.MerchantGradeOnSaleMin`（默认 5）；
   - **银牌** = 铜牌条件 + 本期**计分成功撮合** ≥ `Business.MerchantSilverDealMin`（默认 1）；
   - **金牌** = 铜牌条件 + 本期**计分成功撮合** ≥ `Business.MerchantGoldDealMin`（默认 3）。
   普通档是兜底：未认证、认证但在售不足、或保级期过后不达标，都落在普通。
   在售门槛与匹配机制自洽：`SourcingMatcher` 只匹配公域可见在售的商家，零库存"现找货"本就选不中。
4. **成功撮合的唯一来源**：需求方对自己选定的合作提交成交回执且"谈成"。
   选定（`Adopt`）只是意向不计分；没谈成（没货/加价/拖延/其他）记负信号不计分；不填为中性、不惩罚需求方。
   **终身累计不得作为可降档位的输入**，金库（`TotalEarned`）彻底退出定级、仅作展示。
5. **有效期（核心变更）**：
   - 一期 `Business.MerchantGradeWindowDays`（默认 180）天；升级或续期即重发一整期；
   - 期内本期成交达到下一档要求且认证、在售达标，**立即升级并重发一期**；
   - 到期按本期成交保留能支撑的牌级（银 1 次、金 3 次）；**零成交降至铜牌**并续一期；
   - 续期起点取**原到期日 + 180 天**，巡检晚一两天不会让周期漂移；
   - `Merchant.GradePeriodStartAt`/`GradePeriodEndAt` 落库（迁移 `AddMerchantGradePeriod`，
     存量已定级商户幂等回填 `now` 至 `now + 180 天`）。
6. **在售保级期**：在售跌破门槛时挂 `Merchants.GradeGraceUntil=now+Business.MerchantGradeGraceDays`
   （默认 15 天，0=立即降），期内维持原牌级与成员 buff；恢复在售自动清钟；
   **连续不足超过保级期直接降普通，不等期末**。到期结算只负责成交维度。
7. **升档礼**：升到铜牌 +50 / 银牌 +150 / 金牌 +300 商家金入金库
   （`Business.MerchantGradeBonusLv2/3/4` 可调，0=不发）。BizId=`gradeup:{merchantId}:{档序}`——
   **每商户每档终身一次，复升同档不重发**；与有效期无关，续期不发。
8. **降级纪律**：不回拨已发升档礼、降档无额外惩罚（只停权益）——掉级翻译成召回路径。
9. **判定触发点**：升级由成交回执提交、上架、审核通过即时触发；在售不足由这些重算点加每日巡检判定；
   到期续期或降档只由每日巡检结算。**等级升降与登录、活跃度无关**。
10. **每日巡检**：`MerchantGradeSweepJob` 每日 03:00（UTC+8）扫描全部在职商户重算一次，
    承担到期结算、在售不足降级与到期前 7 天提醒。
11. **牌级详情页**（Taro `pages/merchant/level`）：头部彩牌 + 档位图标 + 到期日（`到期日 yyyy.MM.dd`）
    + 双指标进度（本期成交、在售）+ 距下一档 + 四档阶梯 + 权益清单 + 商家金加减卡 + 等级规则入口；
    数据源 `GET /api/points/merchant-grade?merchantId=`（在职成员校验），
    后端回 `nextTier{requiredOnSale,requiredDeals,metOnSale,metDeals}`、`requiredDeals`、
    `periodStartAt/periodEndAt`、`downgradeTo`，前端不自推阈值组合。
12. **规则页**：不做独立新页，复用 `pages/rules/index?kind=grade`；数据取公开端点
    `GET /api/points/merchant-grade/rules`，阈值随 Admin 调整实时变化，前端只留兜底默认值。
13. **搜索权重加权**：`MerchantGradeExtensions.Rank` 即牌级序数；
    商家搜索主排序与轴承在售商家列表按牌级序数（等级高者靠前），查询期实时打分、不持久化权重字段。

## 四、商家金的口径与消耗边界（v1.3.0 评估结论）

商家金是店铺经营账本，来自升档礼、成员赚币上供、集体任务与挂礼结算；**不参与定级**。
等级页底部把"加"（升档礼、任务奖励）与"减"（兑换置顶等）放在同一张卡展示，
余额与最近流水仅商户管理员可见，非管理员显示"仅管理员可查看与支配"。

**评估并否决的两项消耗/激励**：

| 想法 | 结论 | 理由 |
|---|---|---|
| 购买"保级卡"（用商家金延长保级） | **暂不做** | 已有 15 天保级期；再买只是同一件事的重复延长。当前阶段缺供给与成交，不是缺商家金消耗出口。若上线后数据显示"临时缺货降级"占比高，优先调大 `MerchantGradeGraceDays`，而不是卖卡 |
| 赠送其他商家"下一档等级卡"（邀请入驻获客） | **不做等级卡** | 牌级给买家的信号是"有货、被买家选过"；赠卡会重新打开"空店挂高牌"。若做拉新，只做"邀请入驻双方得商家金"，绝不触碰牌级 |

**长期红线**：凡是让牌级输入被自身输出反哺的机制（钱→等级→更多钱），默认拒绝；
商家金可以买服务、买曝光，不能买时间上的信任豁免。

## 五、数值锚点（节奏调参依据）

- 曲线形态：档距 100/200/300/400/600/800/1000/1200/1400 温和凸递增，前置快后置慢（主流成长等级范式）。
- 日上限=最快升档硬地板（理论极限 ~150 币/日）：Lv10 硬核最快 ~40 天、活跃 ~100 天、轻度 ~500 天；
  首日新手一次性礼可直接冲 Lv2。
- 升档礼全满 +450，占满级阈值 7.5%（正反馈不通胀）。
- 调参阀门：档位阈值/升档礼/一期天数/保级天数/牌级成交阈值均走 SystemConfig，Admin 实时改。
