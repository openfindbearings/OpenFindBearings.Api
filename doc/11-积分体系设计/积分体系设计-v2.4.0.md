# 积分体系设计 v2.4.0（实施进度：M1-c 商家金库与挂礼经济落地）

> 版本：v2.4.0 | 日期：2026-09-27 | 上一版：v2.3.1（发放竞态污染修复）| 设计全貌：v2.1.0
> 本版性质：**实施进度版**——记录 M1-c（金库 + trickle + 挂礼托管结算）实际落地内容。

---

## 一、M1-c 工会经济（已实现，六端绿）

### 1.1 金库账本（与个人积分平行、互不通融）
- `MerchantPointAccount`（键 MerchantId 唯一，Balance/TotalEarned/TotalSpent，xmin 并发令牌）+ `MerchantPointTransaction`（Direction 收/支、GrantType 场景、BizId 部分唯一索引幂等、BalanceAfter 快照）。
- 四类场景常量：`member_trickle`（成员上供）/ `gift_settlement`（挂礼结算）/ `treasury_spend`（金库消费）/ `treasury_burn`（关店燃烧）。
- `IMerchantPointsService` 单一记账入口（懒开户、显式仓储路径）；**SpendAsync 刻意只挂账不提交**——与订单/权益同批 SaveChanges 保原子（v2.3.1 纪律的延续）。
- 参数六键走 SystemConfig（迁移 `20260927004422_AddMerchantTreasury` 内嵌幂等种子，Admin 可改实时生效）：
  `Business.TricklePercent=10`、`TrickleDailyCapPerMerchant=50`、`TrickleMonthlyCapPerMerchant=1000`、`GiftSettleMonthlyCap=2000`、`GiftReceiverMonthlyLimit=3`、`GiftPriceCeiling=3000`。

### 1.2 trickle（成员→工会，定案 §6980-6986 的落地）
- 挂钩点：`PointsService.GrantCoreAsync` 入账成功后调用（白名单在金库服务内部裁决，非白名单直接返回零开销）。
- 白名单（仅"人工审核/真实交易"类）：`correction_adopted / merchant_approved / merchant_profile_complete / merchant_first_product`；**登录/签到/注册明确排除**（无短信验证期的被动可刷项）。
- 算法：T=floor(成员所得×比例)，平分该成员全部在职商户（每家 floor(T/N)），**余数给最早加入的一家**（M2 有等级后改"最高等级家"）；每家再受日顶/月顶约束，顶满即弃（顶是防刷闸不是欠账）。
- 幂等：`trickle:{来源流水bizId}:{商户}`；失败吞掉+warn（金库绝不反噬成员赚分/业务主流程）。

### 1.3 挂礼托管结算（工会摆摊）
- `MallItem` 扩展：`OwnerMerchantId`（null=平台自营）、`AuditState`（0 不适用/1 待审/2 通过/3 驳回）、`AuditRemark`；Icon 列放宽 256 兼作礼品图键。
- 流程：商家申请（仅管理员，默认下架+待审）→ **平台审核定档**（统一定价 ≤GiftPriceCeiling，商家不自定价=断定向转移）→ 自动上架 → 买家兑换走独立 `redeem-gift` 端点（收货三件套必填）。
- 防刷闸：自兑排除升级为**本商户任何在职成员（含员工）不可兑自家礼品**；同址同机月限 3 单（电话或地址任一命中计数，退款单不占额）；发布商户须 Active。
- 托管模型：兑换即扣分（PointTransaction mall_redeem），订单 `ShipStatus` 1 待发货→2 已发货（商家填单号，7 天起算）→3 已收货（买家确认或 Job 自动）→ **全额结算入发布商户金库**（月顶 2000 内，`settle:{订单}` 幂等）。
- 商户退出联动：挂礼自动结算时校验商户仍 Active——已释放/关店的只终止订单不再结算（金库已燃烧，防"释放后再生金"）。
- 争议处置：Admin 对未结算单（ShipStatus 1/2）原路退分 `mall_refund:{订单}`；已收货单不可反冲，走金库侧人工处理。
- `MallAutoConfirmJob`（BackgroundService，每小时）：发货满 7 天未确认 → 自动收货+结算+站内信商家管理员，逐单独立提交互不拖累。

### 1.4 站内信四触点
兑换待发货/已发货/自动结算/争议退款，分别通知商家管理员或买家（`gift_order`/`gift_shipped`/`gift_settlement` 类型，badge 计数复用现有红点体系）。

### 1.5 商户终局与账号清零
- 关店释放/强制 detach：`ResetOperationalDataForReleaseAsync` 新增两步——挂礼批量下架（留行供历史订单快照）+ 金库余额**燃烧**（`burn:{商户}:release`，工会解散仓库回收，同事务提交）。
- 商户硬删（self 通道/驳回删除/注销清理）：`HardDeleteMerchantWithMembersAsync` 连带硬删金库两表 + 挂礼行（Close/Withdraw/DeleteRejected/Deactivate 四个调用点全部补齐注入）。
- 用户注销：兑换订单（含礼品托管单）随账号清零；金库是商户维度账本不受个人注销影响（守卫已强制先转让/关店）。

### 1.6 置顶卡双支付通道（金库的第一个消费出口）
`RedeemAsync` 增加 `useTreasury`：管理员可选"个人积分/商家金库"（前端 ActionSheet 双通道 + 余额前置可见，不足引导去赚），金库支出与订单同事务原子。

### 1.7 端点（14 个新增）
**API 用户/商户侧**：POST /api/merchant/gifts、GET /api/merchant/gifts、POST /api/merchant/gifts/{id}/offshelf、POST /api/merchant/gifts/image、GET /api/merchant/treasury、GET /api/merchant/treasury/transactions、GET /api/merchant/gift-orders、POST /api/merchant/gift-orders/{id}/ship、POST /api/mall/redeem-gift、POST /api/mall/orders/{id}/confirm-receipt。
**API Admin 侧**：GET /api/admin/mall/gifts/pending、POST /api/admin/mall/gifts/{id}/approve、POST /api/admin/mall/gifts/{id}/reject、GET /api/admin/mall/orders/escrow、POST /api/admin/mall/orders/{id}/refund（审核复用 `merchant.verify`、退款复用 `merchant.manage`——**零新增权限键**）。
**BFF 代理 10 个**：/mobile/merchant/treasury|treasury/transactions|gifts|gifts/{id}/offshelf|gifts/image|gift-orders|gift-orders/{id}/ship + /mobile/mall/redeem-gift|orders/{id}/confirm-receipt；redeem 请求体透传 useTreasury；目录/订单响应透传 ownerMerchantName/物流字段。

### 1.8 前端
- **Taro 商城页**：礼品卡片区（"来自 XX 商家"+限量+兑换）；收货信息内嵌面板（RN 无 fixed，作为常规块置于目录之上，昵称/电话从登录资料预填）；我的兑换展示物流态（待商家发货/已发货·待确认/已收货/已退款）+ **确认收货按钮**（二次确认，说明"确认后积分结算给商家"）+ 单号回显。
- **Taro 新页 pages/merchant/gifts（金库挂礼）**：金库余额卡+流水、挂礼申请（名称/描述/数量/图片选拍上传走 pickImage+upload 平台适配）、我的挂礼列表（待审核/在售X分/已驳回+原因/已下架，下架操作）、礼品订单待发货/已发货双页签+填写物流单号发货。商家页操作区新增"金库挂礼"入口（仅管理员）。
- **商品管理置顶**：ActionSheet 双支付通道（管理员）+ 金库余额前置。
- **Admin 商城页重构为三区页签**：平台权益目录（原表格）/ 挂礼待审（缩略图+定档价输入+通过/驳回 showPrompt）/ 托管订单（物流态徽章+争议退款 showPrompt），按钮级显隐走 PanelPerms。

## 二、部署注意事项

1. **API 必须跑迁移** `AddMerchantTreasury`：两表 + MallItems 三列（Icon 放宽 256）+ MallOrders 七列 + 六条 Business.* 配置种子。验证 `__EFMigrationsHistory`。
2. 发布顺序：API → BFF → Admin → Taro；Taro 新页需 Metro 重启（RN 路由表启动期读取）。
3. 无新增权限键，Admin 用户无需强制重登。
4. 端到端验证链：成员赚分（纠错采纳）→ 商家金库 +10% 上供可见 → 申请挂礼 → Admin 定档通过 → 买家商城兑换（收货单）→ 商家发货填单号 → 买家确认收货 → 金库结算流水；关店释放 → 金库燃烧流水 + 礼品自动下架。
