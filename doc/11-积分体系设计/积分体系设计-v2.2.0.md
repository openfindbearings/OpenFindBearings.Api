## 二、M1-a 成就子系统（已实现，四端绿）

### 2.1 设计要点（承 v2.1.0）
- **双层轨**：个人成就（Scope=Personal，OwnerId=UserId）+ 商户成就（Scope=Merchant，OwnerId=MerchantId，B2B 信任信号）。
- **两类货币分离**：
  - **成就点 MetaPoints**：只加不花的荣誉分，解锁即累加到所有者，驱动称号（"最高成就点称号为当前"）；**不是**可花积分。
  - **可花甜头 RewardPoints**：解锁时一次性小额可花积分（个人轨才发，商户轨不发——组织不可花积分，金库仅 MerchantAdmin 平台内花）。
- **仪表 gauge vs 计数器 counter**：
  - gauge（取较大值，永不回退）：连签天数、在售商品数、认证状态、选定次数等"当前值"类。
  - counter（累加）：纠错采纳总数、签到总次数、选定总次数等"历史累计"类。
- **幂等**：解锁判定=`Progress >= Target`；唯一索引 `(Scope, OwnerId, AchievementKey)`；可花甜头 bizId=`ach:{key}:{owner}` 走 GrantAsync 幂等。
- **旁路安全**：所有成就累加 try-catch 吞异常，绝不反噬签到/纠错/上架/认证/寻货主流程。
- **隐藏成就**：Hidden=true 未解锁时墙不显示（防剧透），解锁后显示。

### 2.2 数据模型（迁移 `20260926161808_AddAchievements`）
- `AchievementDefinitions`：Key(唯一)/Name/Description/Icon/Scope/Category/MetricKey/ProgressTarget/MetaPoints/RewardPoints/TitleReward/Rare/Hidden/Enabled。
- `AchievementUnlocks`：Scope/OwnerId/AchievementKey/Progress/UnlockedAt，唯一索引 (Scope,OwnerId,AchievementKey)。
- 迁移内嵌**初始成就目录种子**（15 个，幂等 NOT EXISTS）+ `achievement_unlock` 规则种子（幂等）：
  - 个人·数据共创：correction_first(1)/correction_10/correction_50(称号数据纠错师)/correction_100(稀有,称号数据守护神)
  - 个人·忠诚：checkin_7/checkin_30(称号坚守者)/checkin_100(稀有)/checkin_total_30
  - 个人·寻货：sourcing_selected_first(伯乐)/sourcing_selected_10(金牌红娘)
  - 商户：merchant_first_listing(开张大吉)/merchant_listing_20(货架满满)/merchant_verified(认证商家)/merchant_selected_first(首单中选)/merchant_selected_10(稀有,金牌供应商)
- xmin 并发令牌为纯模型映射，迁移中**不**生成 AddColumn（PG 系统列本就存在）。

### 2.3 领域/应用/基础设施
- `AchievementDefinition`（含 Update 方法：Name/Description/ProgressTarget/MetaPoints/RewardPoints/TitleReward/Enabled 可改，Key/Metric/Scope 不可变）。
- `AchievementUnlock`（含 SetProgress/MarkUnlocked）。
- `IAchievementRepository`/`AchievementRepository`：定义目录 + 一表双轨进度读写。
- `IAchievementService`/`AchievementService`：
  - `IncrementAsync(scope, ownerId, metricKey, delta)` 计数器累加。
  - `SetGaugeAsync(scope, ownerId, metricKey, value)` 仪表取较大值。
  - 两者内部 `EvaluateAsync` 判定解锁→写 UnlockedAt→个人轨发可花甜头→返回新解锁键列表。
  - `GetWallAsync/GetMyAsync/GetMerchantAsync` 墙/徽章排查询（隐藏成就未解锁过滤）。
- `PointTransaction.TypeAchievementUnlock` 常量 + `IPointsService.GrantAsync` 新增 `amountOverride` 可选参数（成就甜头按定义分值发，仍受规则存在/启用/日上限守卫）。

### 2.4 事件接线（事件驱动，零内联依赖）
| 触发源 | 成就 | 机制 |
|---|---|---|
| CorrectionProcessedEvent(Accepted) | correction_adopted 计数 | 新增 `AchievementCorrectionHandler` 订阅 |
| SourcingAdoptedEvent | sourcing_selected(个人)/merchant_selected(商户) 计数 | 新增 `AchievementSourcingHandler` 订阅 |
| BearingPutOnShelfEvent | listing_count 仪表（重算在售数） | 新增 `AchievementListingHandler` 订阅 |
| VerifyMerchantCommandHandler | merchant_verified 仪表 | handler 内旁路调用 SetGauge |
| /api/points/checkin 成功 | checkin_streak 仪表 + checkin_total 计数 | 端点内旁路调用，响应带 unlockedAchievements |

### 2.5 端点
**API（5 个）**
- `GET /api/achievements/wall`（个人成就墙：全目录+进度+成就点合计+当前称号+解锁数）
- `GET /api/me/achievements`（我的已解锁徽章排）
- `GET /api/merchants/{id}/achievements`（商户徽章排，可未登录浏览）
- `GET /api/admin/achievements`（目录全量，system.manage）
- `PUT /api/admin/achievements/{id}`（编辑：分值/阈值/称号/启停，system.manage）

**BFF（3 个代理）**：`/mobile/achievements/wall`、`/mobile/achievements/me`、`/mobile/achievements/merchants/{id}`；CheckinResponse 透传 `unlockedAchievements`。

### 2.6 前端（Taro）
- 新页 `pages/my/achievements`（成就墙：分类分组、未解锁灰显+进度条+如何获得、已解锁点亮+稀有标+称号、顶部成就点/称号/解锁数）。
- 我的页积分卡下方**个人徽章排**（横向滚动，GitHub 成就条/军功章感，整条点进成就墙；未登录/无徽章不占位）。
- 商户详情页头部下方**商户徽章排**（信任信号，徽章越多越牛）。
- 任务中心签到成功若点亮成就→补一条 toast。
- 全部功能页新增"成就墙"入口。

### 2.7 Admin
- 新页 `Achievement/Index`（成就目录管理：按范围/分类分组列表、稀有/隐藏/启停徽章、编辑模态框改名称/描述/目标/成就点/甜头/称号/启停）。
- 菜单"系统配置"组下新增"成就管理"（system.view 可见，编辑 system.manage）。
- 复用既有 system.view/system.manage 权限键，**无新增权限迁移**。

## 三、部署注意事项（M0+M1-a）

1. **API 必须跑迁移** `AddAchievements`：建两表 + 15 成就种子 + achievement_unlock 规则种子。验证 `__EFMigrationsHistory` 出现 `20260926161808_AddAchievements`。
2. xmin 并发令牌为纯模型映射，**无 DDL**；但发布后 PointAccount 写路径开始带并发检查，若历史有脏并发数据可能偶发 DbUpdateConcurrencyException（PointsService 已 try-catch 吞掉返回 0，不阻断）。
3. 成就种子只在迁移落（存量库 SeedData 短路），新装库靠 SeedData+迁移双轨一致。
4. BFF/Taro/Admin 随 API 同批发布；Taro 新增页面需 Metro 重启（RN 路由表启动时读 app.config）。
5. 无新增权限键，Admin 无需权限迁移。

## 四、后续路线（承 v2.1.0，未实施）

- **M1-b 商城虚拟**：商品/订单/结算聚合、DeductAsync 高频、置顶卡/寻货次数包虚拟商品。
