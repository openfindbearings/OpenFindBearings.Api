## 一、总则

1. **状态可枚举**：业务状态一律用枚举，禁止裸 int 常量（Tier2 已把 4 处历史裸 int 收敛为枚举）。
2. **正交分轴**：不同语义的状态**分字段**，不揉进一个值。典型两轴：
   - **审核位**（是否被平台放行）与**销售态**（商家是否在售）正交；
   - **生命周期/软删**（IsActive）与业务状态正交。
3. **公域可见口径**：一个实体"对买家公开"的判定要能一眼写出——商家商品为 `IsActive && ReviewStatus==Approved && SaleState∈{OnSale,Restocking}`。
4. **时间**：一律 UTC（`DateTime.UtcNow`）；"当天"边界走 `BusinessClock`。状态书签时间（ClosedAt/VerifiedAt/ApprovedAt 等）皆 UTC。
5. **软删**：`BaseEntity.IsActive`（所有实体继承）；少量实体另有独立软删（如 `SourcingDemand.IsDeleted`）需注明。

## 二、五类基础数据的状态

| 数据 | 状态/标志位 | 说明 |
|---|---|---|
| **品牌 Brand** | `IsActive`（软删）；`DataSource`（来源）；`Level`（档次，非状态） | 无审核/发布状态 |
| **类型 BearingType** | `IsActive`；`DataSource` | 无审核/发布状态 |
| **轴承 Bearing** | `IsActive`；`IsVerified`/`LastVerifiedAt`/`VerifiedBy`（**数据核验轴**）；`DataSource`；`IsStandard`/`Category` | 核验轴：平台对数据可信度的标记，非审核 |
| **商家 Merchant** | `Status`(MerchantStatus: Active/Suspended/Pending/Draft)；`IsVerified`/`VerifiedAt`/`VerifyRequested`（**资质认证轴**）；`IsDataVerified`/`LastVerifiedAt`/`VerifiedBy`（数据核验轴）；`Grade`/`GradePeriodStartAt`/`GradePeriodEndAt`/`GradeGraceUntil`（牌级/有效期/保级）；`ApplicationMode`；`DataSource`；`IsActive` | 最丰富，多轴并存 |
| **替代品 BearingInterchange** | `IsActive`；`DataSource`；`Confidence`；`IsBidirectional`；`InterchangeType`(字符串，三级 exact/conditional/functional) | 字典化：平台维护、进 API 即生效（无状态位）；平台 CRUD；商家/用户经纠错字段 `interchange` 反馈 |

结论：除 Merchant 外，基础数据状态很薄（多为 来源 + 软删）；审核/发布语义只集中在**商家商品（MerchantBearing）**与**Merchant 入驻/认证**上。

## 三、商家商品 MerchantBearing 状态机（本次统一重点）

### 3.1 两条正交轴

| 轴 | 枚举 | 取值 |
|---|---|---|
| 审核位 | `ListingReviewStatus` | `None=0 仓库中` / `Pending=1 审核中` / `Approved=2 已通过` / `Rejected=3 已驳回` |
| 销售态 | `SaleState` | `OffShelf=0 已下架` / `OnSale=1 出售中` / `Restocking=2 补货中` |

替代旧字段：`IsOnSale`+`IsRestocking`（→SaleState）、`IsPendingApproval`（→ReviewStatus）；**删除僵尸字段 `IsFeatured`**（从无写入，职能由 `PinnedUntil` 接管）。

### 3.2 商家可见状态（由两轴派生）

```
Rejected → 已驳回
Pending  → 审核中
Approved + OnSale     → 出售中
Approved + Restocking → 补货中
Approved + OffShelf   → 已下架
None     → 仓库中
```

### 3.3 状态流转

```
                MoveToWarehouse()             SubmitForApproval()
  (新建) ───────────────► 仓库中(None) ───────────────► 审核中(Pending)
                            ▲                              │
                            │                       ┌──────┴──────┐
                            │                  Approve()      Reject(reason)
                            │                       ▼              ▼
                            │              已通过(Approved)   已驳回(Rejected)
                            │                    │                 │
                            │              PutOnShelf/          (改后重提
                            │              TakeOffShelf/         → Submit)
                            │              Restock(销售态切换)
                            └────────────────────────────────────
```

- `SubmitForApproval`：仓库中/已驳回 → 审核中。
- `Approve`：→ 已通过 + 出售中（通过即上架）。
- `Reject(reason)`：→ 已驳回 + 已下架（公域隐藏，理由落 `ApprovalComment`）。
- `MoveToWarehouse`：商家新建初始态。
- 编辑：仅"已通过"商品改重要字段（价格/规格/备注）→ 重审；仓库中/已驳回保持原态。
- "上架"按钮语义：未通过 → 提交审核；已通过 → 直接上架。

### 3.4 公域可见（三面统一过滤）

```
IsActive && ReviewStatus==Approved && SaleState∈{OnSale,Restocking}
```

统一应用于三面：商城货源流（`SearchMallFeedAsync`）、轴承详情在售商家（`GetMerchantsByBearingQueryHandler`）、商家店铺页（`GetMerchantBearingsByMerchantQueryHandler`）。商家自己的商品管理页**不过滤**（各态都要可见）。

### 3.5 平台审核出口

API：`GET /api/admin/merchant-bearings/pending`、`POST /{id}/approve`、`POST /{id}/reject`（权限 `merchant.verify`）。
Admin：新增「商品审核」页（列表 + 通过/驳回附理由）。此前命令存在但**无端点出口**的空转状态已修复。

### 3.6 删除生命周期（v1.1.0 商家删除）

商家可删除自家商品（**全体成员可删**），按状态守卫分流：

| 状态 | 处理 |
|---|---|
| **出售中 / 补货中** | **禁止**（公域可见，须先下架） |
| 仓库中 / 审核中 / 已驳回 / 已下架 | **物理删除**（硬删，不留软删行） |

- 删除端点为 `DELETE /api/merchant/bearings/{id}`（成员归属校验 + `EnsureRemovable()` 守卫）。
- 硬删使 `(MerchantId, BearingId)` 唯一键**完全释放**，同型号可再次添加；因 `MerchantBearings` 表无软删行，不存在"软删占键"隐患。
- 边角：若该商品被置顶卡兑换过，历史 `MallOrder.TargetRef`（存 MerchantBearingId）硬删后变悬空（无外键约束、不报错，仅历史置顶订单追溯断链，可接受）。

### 3.7 替代品：无状态机（v1.3.0 字典化，撤销 v1.2.0 审核位）

替代关系（BearingInterchange）属平台主数据（字典）——与轴承/品牌/类型同级，进 API 即生效，**不设审核状态位**：

- v1.2.0 的 `ReviewStatus`（已生效/待审核/已驳回）、`ReviewComment`、`ProposedByMerchantId` 与 `InterchangeReviewStatus` 枚举**整体删除**。迁移 `RemoveInterchangeReview` 先物理清除历史"待审核/已驳回"行（从未生效、字典化后无出口），再删三列与 `IX_BearingInterchanges_ReviewStatus`。
- 撤销理由：替代关系是跨品牌等效知识，属主数据；候选提交权交给商家属归域不当，且商家有把 `functional` 说成 `exact` 的利益冲突；爬取候选的审核本已在数据管线侧（staging `IsManuallyApproved`）完成，API 侧再设一道是重复设卡；商家/用户的表达需求由既有**纠错**通道承载。
- 三级替代类型（`InterchangeType`）语义不变：`exact`=标准等效替代；`conditional`=条件替代（需评估）；`functional`=仅供参考（`IsAutoRecommendable=false`，不进自动推荐）。
- 公域读取 `GET /api/bearings/{id}/interchanges` 返回该轴承全部生效关系，按"源∪双向反向"合并（`IsBidirectional` 真正生效），返回含类型标签的 `BearingInterchangeDto`。
- 维护入口：平台 `/api/admin/interchanges`（列表读 `interchange.view` / 新建·编辑·删除写 `interchange.manage`）。数据来源=权威网站抓取（管线侧审核后入库）或平台人工维护（`DataSource` 溯源）。
- 参与方（商家/用户）通道：**纠错**字段 `interchange`（自由文本，描述"哪条不对 / 应补哪条"）；因无法确定性解析为"源→目标"一对轴承，审批**不自动应用**该字段，由平台核实后在替代品管理页落地关系。
- 删除：物理删除（唯一约束 (Source,Target) 释放；历史 `MallOrder`/纠错单引用无外键、悬空可接受）。
