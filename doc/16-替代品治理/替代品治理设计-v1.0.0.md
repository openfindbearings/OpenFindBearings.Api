# 替代品治理设计 v1.0.0

> 版本：v1.0.0 | 日期：2026-10-12 | 状态：已实施（P1+P2）

## 一、定位

轴承"替代关系"不是普通推荐商品，涉及尺寸、精度、游隙、载荷、转速、密封形式、工况适配等专业判断。若完全交给商家维护，易出现"把勉强能用标成可直接替代"的利益冲突与口径不一；若完全由平台维护，又会脱离货源导致"平台标了替代、商家实际供不了"。

因此替代关系采用三方分工：

| 主体 | 负责 | 维护到什么程度 |
|---|---|---|
| **平台** | 建标准、审关系、控风险 | 型号主数据、替代类型、审核规则（黑名单后续） |
| **商家** | 报候选、确认可供性 | 提交本店可交付的替代型号 |
| **采购方/技术方** | 确认工况适配 | 关键设备/高速/高温/重载场景最终确认 |

一句话：**商家提供"候选清单"，平台负责"标准化、审核、展示与责任边界"，采购方负责"最终工况确认"。**

## 二、三级替代类型（`InterchangeType`）

| 值 | 口径 | 自动推荐 |
|---|---|---|
| `exact` | 标准等效替代（同尺寸/精度/结构，可直接替换） | 是 |
| `conditional` | 条件替代（精度/密封/游隙/品牌系列差异，需技术确认） | 是（带"需评估"标签） |
| `functional` | 仅供参考（类似用途，不构成平台推荐） | **否**（仅作人工咨询入口） |

前端统一以 `typeLabel`（标准等效替代 / 条件替代（需评估） / 仅供参考）呈现，并附责任提示。

## 三、审核状态机（`InterchangeReviewStatus`）

| 值 | 语义 | 公域可见 |
|---|---|---|
| `Approved`=0 已生效 | 平台自建 / 商家提交经审核通过 | 是 |
| `Pending`=1 待审核 | 商家提交候选，未生效 | 否 |
| `Rejected`=2 已驳回 | 平台驳回（`ReviewComment` 带理由，提交方可见、可改重提） | 否 |

- 平台自建走 `CreateInterchangeCommand`，直接 `Approved`（平台即审核方）。
- 商家提交走 `SubmitInterchangeCommand`，置 `Pending` 并记录 `ProposedByMerchantId`。
- 公域读取仅返回 `Approved`。

## 四、实现清单

**Domain**
- `BearingInterchange` 增 `ReviewStatus`/`ReviewComment`/`ProposedByMerchantId`；方法 `MarkApproved`/`SubmitByMerchant`/`Approve`/`Reject`/`UpdateDetails`；派生 `IsPubliclyVisible`/`IsAutoRecommendable`。
- 仓储增 `GetApprovedForBearingAsync`（源∪双向反向）、`GetPagedAsync`、`GetPendingAsync`、`GetByProposerAsync`；`DeleteAsync` 改物理删除。
- 值对象 `DataSource.FromUserSubmitted`。
- 迁移 `AddInterchangeReview`（`ReviewStatus` 默认 0=已生效，存量行保持可见）。

**Application**
- 命令：Create/Update/Delete/Approve/Reject（平台）+ Submit（商家）。
- 查询：GetInterchanges（平台列表）/ GetPendingInterchanges（审核队列）/ GetMyInterchanges（商家）/ 公域 GetBearingInterchanges（改返回 `BearingInterchangeDto`）。
- DTO：`BearingInterchangeDto`（公域条目）、`InterchangeAdminDto`（管理行）。

**API 端点**
- 平台（权限 merchant.verify）：`GET /api/admin/interchanges`、`GET /api/admin/interchanges/pending`、`POST /api/admin/interchanges`、`PUT /api/admin/interchanges/{id}`、`DELETE /api/admin/interchanges/{id}`、`POST /api/admin/interchanges/{id}/approve`、`POST /api/admin/interchanges/{id}/reject`。
- 商家：`POST /api/merchant/interchanges`、`GET /api/merchant/interchanges`。
- 公域：`GET /api/bearings/{id}/interchanges`（只放已生效，源∪双向反向）。

**Admin**：替代品管理页（列表/筛选/新建/编辑/删除）+ 替代品审核页（通过/驳回附理由）；修复原失效的"替代品"查看弹窗。

**Taro**：轴承详情替代品区展示三级标签 + 尺寸 + 责任提示；商家"替代提交"页（提交候选 + 我的提交进度/驳回理由）。

**BFF**：替代 DTO 透传新字段；商家提交/我的提交代理。

## 五、责任边界提示

- 展示层统一提示：替代关系经平台审核；"需评估/仅供参考"档请人工确认工况适配。
- `functional`（仅供参考）不进自动推荐。

## 六、后续（P3，预留）

- **证据字段**：品牌授权、样本参数、图纸、历史成交记录。
- **反馈与黑名单**：替代失败反馈扣商户等级分；多次错误替代的商户限制替代推荐权限。
- P3 依赖数据积累，本次仅预留 `ProposedByMerchantId` 追溯字段。
