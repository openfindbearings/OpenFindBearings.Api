## 1. 核心概念

### 1.1 两种数据来源，共存方案

| 来源 | 含义 | 管理方 | 可信度 |
|------|------|--------|--------|
| 爬虫（Crawler） | ETL 从 CBIA 等互联网站点抓取 | Sync 服务自动维护 | 低，用于冷启动填充 |
| 商户自管（Manual） | 认证商户自行上传/维护 | 商户管理员/员工 | 高，商户自行负责 |

**原则：** 爬虫数据作为基础填充，与商户自管数据通过 `DataSourceType` 字段共存。商户认证审核通过时不再清除爬虫数据，数据保留在库中。公共端点 `GET /api/merchants/{id}/bearings` 默认按 Manual 优先展示（可通过 `dataSource` 参数切换），Admin 页面提供"同步数据"弹窗查看爬虫来源记录。Sync L 阶段全量导入所有 MerchantBearing（不跳过已认证商户），`DataSource` 字段显式传入 `"cbia"`。

### 1.2 三种用户类型

| 类型 | 认证方式 | 入口 | 职能 |
|------|----------|------|------|
| 普通用户 | 手机号 + 短信验证码 | Mobile APP | 搜索轴承、浏览商户、关注收藏 |
| 商户管理员 | 普通用户 -> 申请入驻 -> 审核通过 | Mobile APP + Admin | 管理店铺、维护库存、邀请员工 |
| 商户员工 | 被管理员邀请 -> 注册/确认 | Mobile APP | 协助维护库存 |

## 2. 业务流程图

### 2.1 全链路

```
                        普通用户注册（手机号 + 验证码）
                                    |
                           ↓ 想卖货了 ↓
                          申请入驻
                      /               \
                 认领爬虫商户         新建商户
                 （自动填充信息）     （全部手工填写）
                      \               /
                          上传营业执照
                          提交申请
                              |
                          等待审核（PendingReview）
                              |
                     ┌────────┴────────┐
                     ▼                 ▼
              审核通过              审核拒绝
              Merchant.Verify()     已拒绝状态
              标记已认证            可重新申请
              商户管理员可登录
                     |
              ┌──────┴──────┐
              ▼             ▼
        维护库存         邀请员工
        增加/删除/批量   手机号 -> 邀请码
        上架/下架          -> 员工注册/确认
```

**审核通过时的操作：**

1. `Merchant.Verify(verifiedBy)` —— 标记已认证，记录审核人
2. 用户关联：`Merchant.AddStaff(user)`
3. 爬虫数据保留在库中，不再清除；公共端点展示时 Manual 数据优先

## 4. 商户入驻体系

### 4.1 入驻申请（API 项目）

`POST /api/merchant/apply`

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `claimMerchantId` | Guid? | 否 | 认领已有商户 ID，不填则为新建 |
| `name` | string | 认领时否，新建时是 | 商户名称 |
| `contactPerson` | string | 否 | 联系人 |
| `phone` | string | 否 | 联系电话 |
| `address` | string | 否 | 地址 |
| `businessLicenseImage` | string | 是 | 营业执照图片（base64 或文件上传 URL） |

**认领 vs 新建：**

| 方式 | 操作 |
|------|------|
| 认领 | MAUI 搜索爬虫商户名 -> 选中 -> 自动填充名称/地址/联系人 -> 用户确认补充 -> 提交 |
| 新建 | 全部由用户填写 -> 提交 |

**状态机：**

```
Draft（编辑中，未提交）
  -> PendingReview（已提交，等待审核）
    -> Verified（审核通过，成为认证商户）
    -> Rejected（审核拒绝，附拒绝原因，可重新提交申请）
```

### 4.2 审核管理（Admin 项目）

Admin 审核页功能：

| 功能 | 说明 |
|------|------|
| 待审核列表 | 按提交时间排序，显示商户名+申请人+提交时间 |
| 详情查看 | 商户信息 + 营业执照图片预览 |
| 审核通过 | 调用 `POST /api/admin/merchants/{id}/verify`（不再清除爬虫数据） |
| 审核拒绝 | 调用 `POST /api/admin/merchants/{id}/reject`，附带原因 |
| 历史记录 | 显示该商户的审核流水 |
| 同步数据 | 弹窗查看爬虫来源的 MerchantBearing 记录，支持"显示全部"切换 |

### 4.3 已认证商户数据保护

商户认证审核通过后，爬虫数据保留在库中，不再清除。公共端点默认展示 Manual 数据（商户自管），通过 `dataSource` 查询参数可切换到 Crawler 数据视图。Admin 审核页提供"同步数据"弹窗供运营人员查看爬虫来源记录。

**数据展示策略：**

```
GET /api/merchants/{id}/bearings?dataSource=Manual（默认，商户自管）
GET /api/merchants/{id}/bearings?dataSource=Crawler（爬虫数据）
GET /api/merchants/{id}/bearings?onlyOnSale=true（仅展示在售）
```

**Sync L 阶段导入策略：**

```
LoadRelationsAsync 每批：
  └── 全量发送到 API（不跳过已认证商户）
      └── DataSource = "cbia"，对应 MerchantBearing.DataSourceType = Crawler
```

## 6. 商户库存管理

### 6.1 MerchantBearing 现有字段

`MerchantBearing` 实体已有丰富的生命周期管理模型，不重新设计，直接复用：

| 字段 | 类型 | 说明 |
|------|------|------|
| `MerchantId` | Guid | 商户ID |
| `BearingId` | Guid | 轴承ID |
| `PriceDescription` | string? | 价格描述（"55-60元"、"电议"） |
| `NumericPrice` | decimal? | 数值化价格（用于排序筛选） |
| `PriceVisibility` | enum | Public / LoginRequired |
| `StockDescription` | string? | 库存描述（"现货"、"期货"） |
| `MinOrderDescription` | string? | 起订量描述 |
| `Remarks` | string? | 商家备注 |
| `IsOnSale` | bool | 是否在售（商户控制上架/下架） |
| `IsPendingApproval` | bool | 是否需要管理员审核 |
| `IsFeatured` | bool | 是否推荐 |
| `ViewCount` | int | 浏览次数 |

### 6.2 MerchantBearing 新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `DataSourceType` | 枚举（Crawler / Manual） | 区分爬虫数据和商户自管数据 |

`MerchantBearingConfiguration` 中使用简单枚举映射（非 `OwnsOne`），因为仅需要一个枚举字段，不需要完整的 Value Object。

### 6.3 DataSourceType 写入策略

| 位置 | DataSourceType | 说明 |
|------|---------------|------|
| `BatchCreateMerchantBearingsCommandHandler.cs` (Sync) | `Crawler` | L 阶段批量创建爬虫关联数据，DataSource 显式传入 `"cbia"` |
| `CreateMerchantBearingCommandHandler.cs` (API) | `Manual` | 商户自管库存，通过 MerchantEndpoints 创建 |

### 6.4 爬虫库存 vs 商户库存搜索

```
用户搜索轴承 -> 返回结果
  ├─ 认证商户的 MerchantBearing（Source = Manual） -> 优先展示
  └─ 非认证商户的 MerchantBearing（Source = Crawler） -> 标注"信息来源于互联网"展示
```

认证商户爬虫数据保留在库中，但公共端点默认仅展示 Manual 数据。通过 `dataSource=Crawler` 查询参数可查看爬虫数据。

### 6.5 API 端点

| 端点 | 说明 | 认证 |
|------|------|------|
| `GET /api/merchants/{id}/bearings` | 查询商户轴承（支持 dataSource、onlyOnSale 参数） | 匿名 |
| `GET /api/merchant/bearings` | 查看自己库存 | Bearer（商户管理员/员工） |
| `POST /api/merchant/bearings` | 添加在售轴承（单条） | Bearer（商户管理员/员工） |
| `DELETE /api/merchant/bearings/{id}` | 下架 | Bearer（商户管理员/员工） |
| `POST /api/merchant/bearings/batch` | Excel 批量导入 | Bearer（商户管理员） |

## 8. 已确认的设计决策

### 8.1 ETL 与商户认证的交互策略

**决策：** 爬虫数据保留，通过 DataSourceType 字段区分，认证审核不再清除数据。

**理由：** 认证商户需要查看爬虫导入的初始库存数据作为参考。Admin 运营人员通过"同步数据"弹窗查看爬虫来源记录，便于数据核对。公共端点通过 `dataSource` 参数控制展示范围，Manual 数据优先。

**实现方式：**
1. 审核通过时不再调用 `DeleteByMerchantAndSourceAsync`，数据保留
2. L 阶段全量导入所有 MerchantBearing（不跳过已认证商户），`DataSource` 显式传入 `"cbia"`
3. `GET /api/merchants/{id}/bearings` 新增 `dataSource`（枚举：Manual/Crawler）和 `onlyOnSale`（bool）查询参数
4. Admin 审核页新增"同步数据"弹窗，支持"显示全部"切换

### 8.2 其他讨论（同 v1.0.0）

- 商户认领冲突：一个爬虫商户只能被一个申请认领
- 验证码有效期：5分钟，发送间隔60秒，日上限10次，开发环境固定 123456
- 营业执照图片：开发环境存 base64，生产环境使用 OSS
- 商户员工角色：管理员可管理全部，员工仅库存 CRUD
- MAUI 极简版：5 个页面按 Step 顺序实现

## 9. 实施顺序

| Step | 内容 | 涉及项目 | 后端 | MAUI 页面 |
|------|------|----------|------|-----------|
| 1 | SMS 授权流程 | Identity | send-code + grant_type=sms + signup | 注册/登录页 |
| 2 | 商户入驻 | API + Identity | apply + 认领 + 新建 | 入驻申请页 + 状态页 |
| 3 | Admin 审核页 | Admin | reject + license preview + search + verify（不再清除）+ 同步数据弹窗 | 无 |
| 4 | 员工邀请 | API + Identity | invite + invite_code 消费 | 员工邀请页 |
| 5 | 库存管理 + 数据源过滤 | API + Sync + Admin | bearing CRUD + DataSource 标记 + dataSource/onlyOnSale 查询参数 + 同步数据弹窗 | 库存管理页 |
| 6 | API 端点清理 | API | 移除 batch-check-verified、DeleteByMerchantAndSourceAsync、GetVerifiedNamesAsync | 无 |
| 7 | Sync 预检移除 | Sync | 移除 BatchCheckMerchantsVerifiedAsync 调用、verified pre-check 块 | 无 |
