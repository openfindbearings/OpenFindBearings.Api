## 概述

本文档规划 OpenFindBearings 平台价格数据的全链路设计与配置项消费方案。覆盖 4 个价格相关 SystemConfig 配置项的语义、字段映射、消费链路与展示规范。

v0.2.0 在 v0.1.0 讨论稿基础上，记录了 Admin 端与 API 端的实际落地实现，并说明与初稿设计的差异。

## 一、价格数据模型

### 1.1 实体字段

`MerchantBearing` 实体已包含 4 个价格相关字段：

| 字段 | 类型 | 含义 |
|------|------|----------|
| `PriceDescription` | `string?` | 价格描述文本（"¥55-60"、"电议"、"面议"） |
| `NumericPrice` | `decimal?` | 数值化价格（用于排序与价格区间筛选） |
| `PriceVisibility` | `PriceVisibility`（Public / LoginRequired） | 可见性枚举 |
| `IsNegotiable()` | 方法 | 文本包含"电议"或"面议"时为 true |

DTO `MerchantBearingDto` 暴露 `IsNegotiable`（计算属性）与 `IsPriceVisible`（按 PriceVisibility + 当前用户登录状态计算）。

### 1.2 参考价（待设计）

`Bearing` 实体待新增 `ReferencePrice` 字段（`decimal?`），用于"无在售商家时的兜底价格"。详见独立讨论稿《参考价计算机制设计 v0.1.0》。

## 二、价格相关 SystemConfig 配置项

4 个价格配置项定义于 `SystemConfigs` 表的 `Price` 分组：

| 配置键 | 默认值 | 类型 | 作用 | v0.1.0 状态 | v0.2.0 状态 |
|--------|--------|------|------|-------------|-------------|
| `Price.DefaultVisibility` | `LoginRequired` | string | 新建商家-轴承关联时的默认可见性 | ❌ 未消费 | ✅ 已消费 |
| `Price.ShowNegotiableLabel` | `true` | bool | 商品价格为"电议/面议"时，前端是否显示"议价"标签 | ❌ 未消费 | ✅ 已消费（Admin 端） |
| `Price.NumericForSorting` | `true` | bool | 是否允许按 `NumericPrice` 排序 | ❌ 未消费 | ✅ 已消费（API 端） |
| `Price.ExtractPattern` | `¥(\d+(?:\.\d+)?)` | string | 从价格文本提取数值的正则 | ❌ 配置项缺失 | ✅ 新增并消费 |

**v0.1.0 现状：** 配置项虽写入数据库，但无任何代码根据这些值改变行为；`NumericPrice` 与 `PriceVisibility` 是"死字段"——实体提供了 `SetPrice` 方法，但所有创建与导入路径均只调用 `UpdateMarketInfo`（仅赋值 `PriceDescription`），导致这两个字段恒为默认值。

## 三、价格配置项消费实现（v0.2.0）

### 3.1 新增基础设施组件

#### `Domain/Services/PriceParser.cs`（领域服务，静态）

职责：从多样的价格描述文本中提取数值价格，属纯领域逻辑，不依赖基础设施。

| 方法 | 说明 |
|------|------|
| `ExtractNumericPrice(description, pattern)` | 用配置正则提取首个捕获组的数值；描述为空、正则无匹配、`decimal` 转换失败时返回 `null` |
| `ParseVisibility(value)` | 将配置文本转换为 `PriceVisibility` 枚举；无法识别时返回 `LoginRequired`（偏保守，防止价格被过度公开） |

健壮性设计：
- 正则执行设 200 毫秒超时，避免管理员配置了灾难性回溯的表达式导致请求挂死
- `ArgumentException`（正则语法非法）与 `RegexMatchTimeoutException` 均被捕获并降级为"不解析"，不阻断主流程

#### `Application/Services/IPriceConfigProvider.cs`

职责：为应用层各处理器统一提供价格配置。

#### `Infrastructure/Services/PriceConfigProvider.cs`

职责：从 `SystemConfigs` 表读取 4 项价格配置并做进程内缓存。

| 设计点 | 说明 |
|--------|------|
| 生命周期 | `Singleton` |
| 仓储解析 | 通过 `IServiceScopeFactory` 创建作用域解析 Scoped 的 `ISystemConfigRepository` |
| 缓存 | 5 分钟 TTL，与 Sync 的 `IReliabilityConfigProvider` 保持一致 |
| 并发保护 | `SemaphoreSlim` + 双重检查，避免缓存过期瞬间并发查库击穿 |
| 失败降级 | 数据库不可用等异常时记 Warning 日志并返回代码默认值，保证 ETL 与 Excel 导入链路不中断 |

### 3.2 各配置项消费点

#### `Price.ExtractPattern` + `Price.DefaultVisibility`

| 消费点 | 文件 | 行为 |
|--------|------|------|
| 商家自管创建 | `CreateMerchantBearingCommandHandler` | 创建关联后调用 `SetPrice(描述, 数值价格, 可见性)` |
| 批量导入 / L 阶段 | `BatchCreateMerchantBearingsCommandHandler` | 循环外读一次配置（提供器内有缓存）；新建路径调 `SetNumericPrice` + `SetPriceVisibility`，更新路径同样同步，避免逐条查库 |

#### `Price.NumericForSorting`

| 消费点 | 文件 | 行为 |
|--------|------|------|
| 公开搜索排序 | `SearchMerchantBearingsQueryHandler` | `sortBy=price` 时先读配置，关闭则置空 `sortBy` 回退时间倒序并记日志 |
| 商家在售商品排序 | `GetMerchantBearingsByMerchantQueryHandler` | 同上，回退时间排序 |

两处均做守卫而非依赖调用方自觉，确保配置在服务端真正生效。

#### `Price.ShowNegotiableLabel`

**实现路径（与 v0.1.0 设计稿的差异）：**

v0.1.0 建议在 `MerchantBearingDto` 增加 `ShowNegotiableLabel` 计算属性，让前端免调配置接口。实际未采用该方案，原因：
- DTO 映射属 Application 层，为计算该属性需在映射扩展中注入配置提供器，会让每次映射都产生额外依赖
- Admin 端已有 `PriceConfigService`（Singleton + 5 分钟缓存）统一获取价格配置，职责更清晰

实际实现：Admin `DataController.Merchants` 预加载配置写入 `ViewBag.PriceConfig`，视图序列化为 `window.PRICE_CONFIG` 供 JS 渲染 `[议价]` 角标时判断；`ConfigController.Update` 在配置变更时调用 `PriceConfigService.Invalidate()` 主动失效缓存。

### 3.3 附带修复的既有缺陷

| 缺陷 | 说明 |
|------|------|
| 编译错误 | `GetMerchantBearingsByMerchantQueryHandler.cs` 缺少 `using OpenFindBearings.Domain.Entities;`，导致 `MerchantBearing` 类型无法解析，API 项目无法编译 |
| 死字段 | `NumericPrice` / `PriceVisibility` 此前从未被赋值，价格排序与可见性控制形同虚设 |
| 配置项缺失 | `Price.ExtractPattern` 仅被 `GetPriceConfigQueryHandler` 读取，但 SeedData 从未写入该键，属配置悬空 |

## 四、缓存策略

| 层级 | 组件 | TTL | 失效方式 |
|------|------|-----|----------|
| API 进程内 | `PriceConfigProvider` | 5 分钟 | TTL 自然过期 |
| Admin 进程内 | `PriceConfigService` | 5 分钟 | TTL 自然过期 + 配置更新时主动 `Invalidate()` |

跨进程（多个 API 副本、Sync、MAUI 后端）的配置同步本期依赖 TTL 自然过期，不引入配置变更事件总线——价格配置变更频率极低，5 分钟窗口可接受。

## 五、价格展示规范

### 5.1 Admin 端（v0.2.0 已实施）

**系统配置页（/Config/Index）：** 4 个价格配置项归入"价格显示"卡片组，提供实时编辑；保存后主动失效 Admin 进程缓存。

**在售商品弹窗：** 价格列根据 `IsNegotiable && ShowNegotiableLabel` 决定是否加 `[议价]` 角标；列头点击排序受 `NumericForSorting` 控制，关闭时提示"价格排序已关闭"。

**创建/导入商品：** 可见性由服务端按 `Price.DefaultVisibility` 写入，前端无需传值。

### 5.2 MAUI 端（待实施）

**询价页（首页/查询）：** 轴承卡片增加"最低价 ¥XX 起"行，未登录显示"登录查看价格"。

**轴承详情页（待新建）：** 价格专区展示：
- 参考价（基于同型号同品牌商家报价均值）
- 在售商家列表：商家名 / 价格描述 / `[议价]` 角标 / 库存 / 起订量

**商家详情页（待新建）：** 该商家在售商品列表，含价格描述与 `[议价]` 角标。

### 5.3 API 响应规范

`MerchantBearingDto` 价格字段无论配置如何**始终返回**，可见性由前端按 `IsPriceVisible` 决定如何显示，不在 DTO 上做条件省略（保持 API 稳定）：

| 字段 | 说明 |
|------|------|
| `PriceDescription` | 原文本 |
| `NumericPrice` | 数值（可能为 null） |
| `PriceVisibility` | 枚举值 |
| `IsPriceVisible` | 计算后（按 PriceVisibility + 用户登录状态） |
| `IsNegotiable` | 计算后（文本含"电议/面议"） |

## 七、部署注意事项

服务器上已存在的 `SystemConfigs` 数据需执行以下 SQL 使分组与新增配置项生效：

```sql
-- 删除无消费方配置项
DELETE FROM "SystemConfigs"
WHERE "Key" IN ('EnableRegistration','RequireEmailVerification','DefaultUserRole','ItemsPerPage')
   OR "Key" LIKE 'Cache.%';

-- 修正分组归属
UPDATE "SystemConfigs" SET "Group" = 'Site'
WHERE "Key" IN ('SiteName','SiteDescription','Site.BeiAn','Site.CustomerService');
UPDATE "SystemConfigs" SET "Group" = 'Price' WHERE "Key" LIKE 'Price.%';
UPDATE "SystemConfigs" SET "Group" = 'Sync'
WHERE "Key" LIKE 'RateLimit.%' OR "Key" LIKE 'Reliability.%';
```

`Price.ExtractPattern` 由 API 启动时的 SeedData 幂等补全逻辑自动插入，无需手工 INSERT。
