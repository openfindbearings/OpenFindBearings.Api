**状态：** 待评审

## 概述

本文档规划 OpenFindBearings 平台"参考价"（Reference Price）的生成、存储、刷新与展示机制。**参考价**定义为：当某个轴承尚无在售商家报价（`MerchantBearing.NumericPrice` 为空）时，系统基于同型号同品牌的其他轴承的报价数据计算出的兜底价格。

参考价不阻塞 T 阶段主流程——T 阶段完成后异步计算，下次 T 重跑时刷新。

## 一、需求背景

### 1.1 业务场景

- 用户在 MAUI 询价页搜索型号 "6204-2RS"，数据库无任何商家在售。
- 询价页 / 详情页需要展示一个**有意义的价格**（不是空白），帮助用户判断市场行情。
- 参考价不是商家真实报价，是"基于同型号同品牌其他商家的均价"。

### 1.2 与"在售最低价"的关系

| 概念 | 含义 | 数据源 | 实时性 |
|------|------|--------|--------|
| 在售最低价 (`MinPrice`) | 该轴承有在售商家时取最低 `NumericPrice` | `MerchantBearing` | 实时 |
| 参考价 (`ReferencePrice`) | 该轴承无在售时取同型号同品牌均价 | `MerchantBearing` 聚合 | 异步（每日刷新） |

**优先级：** `MinPrice` 有值时显示 `MinPrice`，无值时显示 `ReferencePrice`，两者都无值时显示"暂无报价"。

## 二、数据模型

### 2.1 Bearing 实体新增字段

```csharp
public class Bearing : AggregateRoot
{
    // ... 现有字段 ...

    /// <summary>
    /// 参考价（基于同型号同品牌其他商家报价均值）
    /// 异步计算，不阻塞 T 阶段
    /// </summary>
    public decimal? ReferencePrice { get; private set; }

    /// <summary>
    /// 参考价计算时间（UTC）
    /// </summary>
    public DateTime? ReferencePriceUpdatedAt { get; private set; }

    /// <summary>
    /// 参考价来源（基于多少家商家的均价）
    /// </summary>
    public int? ReferencePriceSampleSize { get; private set; }
}
```

**EF 配置：**
- `ReferencePrice`：`numeric` nullable
- `ReferencePriceUpdatedAt`：`timestamp with time zone` nullable
- `ReferencePriceSampleSize`：`integer` nullable
- 不建唯一索引（允许 null）

### 2.2 DTO 透出

`BearingDto` 增加：
- `ReferencePrice: decimal?`
- `ReferencePriceUpdatedAt: DateTime?`（返回 UTC）
- `ReferencePriceSampleSize: int?`（N 商家均值）

`MobileBearingLightDto` 仅透出 `ReferencePrice`（轻量列表不需要展示计算时间和样本数）。

## 三、计算口径

### 3.1 输入

- 目标轴承 `(PartNumber, BrandName)` 组合
- 同 `(PartNumber, BrandName)` 且有 `NumericPrice` 非空、`IsOnSale=true` 的 `MerchantBearing` 集合

### 3.2 计算公式

```
ReferencePrice = AVG(NumericPrice)  // 算术平均值
ReferencePriceSampleSize = COUNT(*)
```

**舍入：** 四舍五入到整数（人民币元）。`Math.Round(avg, 0, MidpointRounding.AwayFromZero)`。

**置信阈值：** `SampleSize < 3` 时不计算参考价（样本量不足，宁缺毋滥），置 null。

**排除项：**
- 价格为 0 的记录（视为无效）
- `PriceVisibility != Public` 的记录（公开价才参与）
- `IsOnSale = false` 的记录

### 3.3 边界场景

| 场景 | 行为 |
|------|------|
| 目标轴承自身有在售 | `ReferencePrice` 仍计算并存储（用于此轴承下架后立即可用） |
| 目标轴承无同型号同品牌在售 | `ReferencePrice = null` |
| 目标轴承无品牌（`BrandName` 空） | `ReferencePrice = null` |
| 样本全部 `IsNegotiable` | `ReferencePrice = null`（议价无可比性） |

## 四、计算时机

### 4.1 触发方式

**每日 T 阶段完成后异步执行**（不阻塞 T→L 链路）：

```
T 阶段 Success
    ↓
插入 ImageDownload etl_task（已存在）
    ↓
插入 ReferencePrice etl_task（新增）
    ↓
ReferencePrice handler 异步遍历 Bearing
    ↓
L 阶段继续执行（不被 ReferencePrice 阻塞）
```

### 4.2 实现方式

新增 `EtlCommandType.ReferencePrice` + `ReferencePriceTaskHandler`：

- 与现有 ETL 任务共用 `etl_tasks` 表
- 与 `Images` 任务同样的"不阻塞"语义：失败不影响其他阶段
- 单独 CronJob 调度：`0 6 * * *`（T 完成后 1 小时）

### 4.3 全量 vs 增量

**本期实现：全量重算**（每日遍历全部 `Bearing` 记录）。

**后续优化：** 增量计算（仅重算有 `MerchantBearing` 变更的轴承）。本期数据量下全量足够。

## 五、存储与查询

### 5.1 数据库

直接在 `Bearing` 表加 3 个字段，不新增独立表。理由：
- 一对一关系
- 与 `Bearing` 生命周期一致
- 查询简单（无需 JOIN）

### 5.2 API 查询

`MobileBearingLightDto` 查询 SQL 调整为：

```sql
SELECT b.*,
    (SELECT MIN(mb."NumericPrice")
     FROM "MerchantBearings" mb
     WHERE mb."BearingId" = b."Id" AND mb."IsOnSale" = true) AS "MinPrice",
    b."ReferencePrice"
FROM "Bearings" b
WHERE ...
```

### 5.3 Admin 展示

- **基础信息列表（轴承）：** 不展示参考价（数据量太大，不必要）
- **审核页（编辑弹窗）：** 不展示
- **在售商品弹窗：** 价格列下方小字"参考价 ¥XX（基于 N 家）"（仅当此商家 `NumericPrice` 为空时显示）
- **数据管理：商家详情（待新建）：** 商家在售列表中每行展示参考价

## 六、性能预估

### 6.1 计算量

- 轴承总量：~3 万（db_api `Bearings` 表当前规模）
- 每轴承 SQL：1 次聚合查询（同 `(PartNumber, BrandName)`）
- 总 SQL 数：~3 万次
- 单次 SQL 耗时：< 5ms
- **总耗时：~2.5 分钟**（在缓存预热后）

### 6.2 批量优化

本期实现允许每次单独 SQL（简化代码）。后续若数据量超 10 万，可改为：

```sql
-- 一次性聚合所有同型号同品牌
SELECT b."Id" AS "BearingId",
    AVG(mb."NumericPrice") AS "ReferencePrice",
    COUNT(mb."Id") AS "SampleSize"
FROM "Bearings" b
LEFT JOIN "MerchantBearings" mb
    ON mb."BearingId" = b."Id"
    AND mb."IsOnSale" = true
    AND mb."PriceVisibility" = 0  -- Public
    AND mb."NumericPrice" > 0
WHERE b."BrandName" IS NOT NULL
GROUP BY b."Id";
```

单次 SQL 完成全量重算，~10 秒。

## 七、待评审事项

1. **价格类型：** 参考价是"均值"还是"中位数"？建议均值（用户已习惯"市场参考价 = 均值"概念），数据量小不易被异常值影响。
2. **样本阈值：** `SampleSize < 3` 不计算，是否合理？建议保持（太少参考意义不足）。
3. **跨品牌同型号：** 同 `PartNumber` 但不同品牌的轴承不互相参考（如 SKF-6204 与 NSK-6204 价格差异大）。建议以 `(PartNumber, BrandName)` 为聚合键。
4. **调度时机：** T 完成后 1 小时（06:00 UTC），还是 L 完成后立即（05:30 UTC）？建议放在 06:00 UTC（避开 L 阶段写入高峰）。
5. **价格类型（批发/零售）：** 当前 `MerchantBearing` 仅有单一价格字段。是否需要后续支持"区分批发/零售的参考价"？建议本期不引入（复杂度收益不匹配）。
6. **历史价格趋势：** 是否记录参考价历史（用于走势图）？建议本期不引入，数据量大且 UI 复杂度高。
