## 1. 架构概述

### 1.1 认证与授权分离

| 层级 | 职责 | 项目 |
|------|------|------|
| **认证（Authentication）** | OIDC 令牌签发、用户登录/登出、Token 刷新 | OpenFindBearings.Identity |
| **授权（Authorization）** | 系统级 Scope（admin/mobile/sync） | OpenFindBearings.Identity |
| **RBAC** | 细粒度角色-权限映射 | 各业务系统自行管理 |

OpenFindBearings.Identity 只负责 OIDC 认证和系统级 Scope，不管理各系统的细粒度 RBAC。每个业务系统（Admin、Sync、Crawler）自行维护角色-权限映射。

### 1.2 平台级角色 vs 商户域角色（v1.5.0）

| 维度 | 角色 | 存储 | 判定方式 |
|------|------|------|----------|
| 平台级（全局 RBAC） | Individual / Admin / SuperAdmin | `UserRoles` + `Roles` 表（API SeedData） | RequirePermission(权限键) / 全局 RBAC 查询 |
| 商户域 | MerchantAdmin / MerchantStaff | `MerchantMembers` 表（成员行 Role 字段） | **按 (用户, 商户) 成员行维度查库**，不信 JWT role claim |

> 关键变化：v1.5.0 之前 MerchantAdmin/MerchantStaff 存在全局 `UserRoles` 中，现迁移到 `MerchantMembers` 成员行。API SeedData 仍保留 MerchantAdmin/MerchantStaff 全局角色定义（存量兼容），但**业务鉴权不再以它们为依据**。

### 1.3 Admin RBAC 存储

Admin 项目拥有独立 PostgreSQL 数据库 `db_admin`，包含以下权限相关表：

| 表名 | 用途 |
|------|------|
| `admin_user_roles` | 用户-角色映射 |
| `admin_role_permissions` | 角色-权限映射（种子数据初始化） |
| `admin_audit_logs` | 操作审计日志 |
| `admin_configs` | 系统配置 |

业务数据通过各项目 API 代理访问，不直连业务数据库。

### 2.2 Admin 端 PermissionKey 枚举

```csharp
public enum PermissionKey
{
    DashboardView,      // 查看仪表盘
    BearingView,        // 查看轴承列表
    BearingCreate,      // 创建轴承（品牌/类型/轴承）
    BearingEdit,        // 编辑轴承
    BearingDelete,      // 删除轴承（软删除）

    MerchantVerify,     // 商家认证审核
    SyncTrigger,        // 触发 ETL 任务（注：SyncClient 策略不经过此权限）
    SyncView,           // 查看同步状态
    CrawlerView,        // 查看爬虫状态
    CrawlerTrigger,     // 触发爬虫运行
    DataRestore,        // 恢复已删除数据
    DataHardDelete,     // 彻底删除数据（超级管理员专属）
    UserManage,         // 管理用户
    RoleManage,         // 管理角色和权限

    CrawlerManage,      // 爬虫管理
    SystemView,         // 查看系统配置
```

## 4. 商户域鉴权（v1.5.0 核心变更）

### 4.1 商户域角色判定

| 能力 | 判定方式 | 代码落点 |
|------|----------|----------|
| 是否为商户管理员 | 查 MerchantMember（当前用户 + CurrentMerchantId 商户维度），Role=MerchantAdmin 且 Status=Active | `PermissionService.IsMerchantAdmin()` |
| 是否为商户员工 | 查 MerchantMember（用户 + 商户维度）存在 Active 成员行 | `PermissionService.IsMerchantStaffAsync(merchantId)` |
| 是否有权操作某轴承 | 当前用户必须是该商户 Active 成员，且轴承属于该商户 | `PermissionService.CanManageBearingAsync(bearingId)` |
| 当前商户上下文 | 请求头 `X-Merchant-Id`（必须是该用户在职成员商户，否则回退缺省 = 首个 Active 成员商户） | `UserContextMiddleware` → `ICurrentUserService.CurrentMerchantId` |

### 4.2 IsMerchantAdmin 恒 false 修复

- **原缺陷**（v1.5.0 前）：`PermissionService.IsMerchantAdmin()` 读取 JWT role claim，而 JWT 的 role 来自 Identity 库（仅 SuperAdmin/Admin/User/TestUser），业务侧 MerchantAdmin 在 API 库 → 恒 false → AddStaff/RemoveStaff 管理端校验形同虚设。
- **修复**：`IsMerchantAdmin()` 改为查 `MerchantMemberRepository.GetActiveByUserAndMerchantAsync`（先决条件：已认证 + CurrentMerchantId 有效），返回成员 IsAdmin。
- 关联改造：AddStaffCommandHandler、RemoveStaffCommandHandler、SuspendMerchantMember/ActivateMerchantMember/ChangeMerchantMemberRole、四个 MerchantBearing 操作 handler（PutOnShelf/TakeOffShelf/UpdateMerchantBearing/SetPriceVisibility）均改为按成员表 + CurrentMerchantId 判定所属商户。

### 4.3 一人多商户语义

- 一个用户可通过 MerchantMember 属于多个商户，在各商户的角色相互独立（A 商户 Admin + B 商户 Staff）。
- 商户级操作必须在请求中携带/解析当前商户上下文（X-Merchant-Id）。
- 用户级数据（收藏/关注/浏览历史）与商户上下文无关，切换商户不影响。

## 6. 认证集成方案（已实施）

### 6.1 OAuth 2.0 授权码流程

```
用户浏览器 → Admin 登录页 → Identity /connect/authorize
    → 用户登录授权
    → 回调 Admin /Account/Callback?code=xxx
    → Admin 用 code 换 token（POST /connect/token）
    → BearerTokenHandler 从 cookie 提取 JWT 注入 API 请求
```

### 6.2 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| Admin 认证 | Cookie（CookieAuthenticationDefaults） + JWT Bearer（ApiClient） | BearerTokenHandler 自动转发 JWT |
| Token 交换 | 直接 HTTP 调用 Identity /connect/token | 简单直接 |
| Token 刷新 | BearerTokenHandler 透明处理 | 无感刷新 |

### 6.3 Admin 配置项

```json
{
  "Identity": {
    "Authority": "https://localhost:7201",
    "ClientId": "admin_client",
    "ClientSecret": "admin-secret-key",
    "CallbackPath": "/callback"
  }
}
```

### 6.4 权限校验流程

1. 请求进入 Admin → Cookie 认证
2. BearerTokenHandler 从 cookie 中提取 access_token
3. API 请求携带 `Authorization: Bearer {access_token}`
4. API 端 JWT Bearer 验证 token 有效性
5. 查询 `admin_user_roles` 获取用户角色
6. 查询 `admin_role_permissions` 获取角色权限
7. PermissionEndpointFilter 检查所需权限

## 7. 数据库 Schema

### 7.1 admin_user_roles

```sql
CREATE TABLE admin_user_roles (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    role_name VARCHAR(50) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 7.2 admin_role_permissions

```sql
CREATE TABLE admin_role_permissions (
    id UUID PRIMARY KEY,
    role_name VARCHAR(50) NOT NULL,
    permission_key VARCHAR(50) NOT NULL,
    granted BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 7.3 admin_audit_logs

```sql
CREATE TABLE admin_audit_logs (
    id UUID PRIMARY KEY,
    user_id UUID,
    action VARCHAR(50) NOT NULL,
    entity_type VARCHAR(50) NOT NULL,
    entity_id UUID,
    old_value JSONB,
    new_value JSONB,
    ip_address VARCHAR(45),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 7.4 admin_configs

```sql
CREATE TABLE admin_configs (
    id UUID PRIMARY KEY,
    config_key VARCHAR(100) NOT NULL UNIQUE,
    config_value TEXT,
    description VARCHAR(500),
    updated_by UUID,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```
