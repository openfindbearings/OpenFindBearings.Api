## 1. 架构概述

### 1.1 认证与授权分离

| 层级 | 职责 | 项目 |
|------|------|------|
| **认证（Authentication）** | OIDC 令牌签发、用户登录/登出、Token 刷新 | OpenFindBearings.Identity |
| **授权（Authorization）** | 系统级 Scope（admin/mobile/sync） | OpenFindBearings.Identity |
| **RBAC** | 细粒度角色-权限映射 | 各业务系统自行管理 |

OpenFindBearings.Identity 只负责 OIDC 认证和系统级 Scope，不管理各系统的细粒度 RBAC。每个业务系统（Admin、Sync、Crawler）自行维护角色-权限映射。

### 1.2 Admin RBAC 存储

Admin 项目拥有独立 PostgreSQL 数据库 `db_admin`，包含以下权限相关表：

| 表名 | 用途 |
|------|------|
| `admin_user_roles` | 用户-角色映射 |
| `admin_role_permissions` | 角色-权限映射（种子数据初始化） |
| `admin_audit_logs` | 操作审计日志 |
| `admin_configs` | 系统配置 |

业务数据通过各项目 API 代理访问，不直连业务数据库。

## 5. 认证集成方案（已实施）

### 5.1 OAuth 2.0 授权码流程

```
用户浏览器 → Admin 登录页 → Identity /connect/authorize
    → 用户登录授权
    → 回调 Admin /Account/Callback?code=xxx
    → Admin 用 code 换 token（POST /connect/token）
    → BearerTokenHandler 从 cookie 提取 JWT 注入 API 请求
```

### 5.2 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| Admin 认证 | Cookie（CookieAuthenticationDefaults） + JWT Bearer（ApiClient） | BearerTokenHandler 自动转发 JWT |
| Token 交换 | 直接 HTTP 调用 Identity /connect/token | 简单直接 |
| Token 刷新 | BearerTokenHandler 透明处理 | 无感刷新 |

### 5.3 Admin 配置项

```json
{
  "Identity": {
    "Authority": "https://localhost:7201",
    "ClientId": "admin_client",
    "ClientSecret": "admin-secret-key",
    "CallbackPath": "/callback"
  }
}
```

### 5.4 权限校验流程

1. 请求进入 Admin → Cookie 认证
2. BearerTokenHandler 从 cookie 中提取 access_token
3. API 请求携带 `Authorization: Bearer {access_token}`
4. API 端 JWT Bearer 验证 token 有效性
5. 查询 `admin_user_roles` 获取用户角色
6. 查询 `admin_role_permissions` 获取角色权限
7. PermissionEndpointFilter 检查所需权限

## 6. 数据库 Schema

### 6.1 admin_user_roles

```sql
CREATE TABLE admin_user_roles (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    role_name VARCHAR(50) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 6.2 admin_role_permissions

```sql
CREATE TABLE admin_role_permissions (
    id UUID PRIMARY KEY,
    role_name VARCHAR(50) NOT NULL,
    permission_key VARCHAR(50) NOT NULL,
    granted BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 6.3 admin_audit_logs

```sql
CREATE TABLE admin_audit_logs (
    id UUID PRIMARY KEY,
    user_id UUID,
    action VARCHAR(50) NOT NULL,
    entity_type VARCHAR(50) NOT NULL,
    entity_id UUID,
    old_value JSONB,
    new_value JSONB,
    ip_address VARCHAR(45),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 6.4 admin_configs

```sql
CREATE TABLE admin_configs (
    id UUID PRIMARY KEY,
    config_key VARCHAR(100) NOT NULL UNIQUE,
    config_value TEXT,
    description VARCHAR(500),
    updated_by UUID,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```
